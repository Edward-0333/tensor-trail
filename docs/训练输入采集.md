# 从真实训练输入加载 data

2026-11-04：提供可选 Python 适配器，将真实 `forward(data)` 的字段类型和形状加载到 Tensor Trail 项目。网页本身仍不依赖 PyTorch。

## 静态图与快照分离

2026-11-10 起，更新工具不再用某次 batch 的 shape 覆盖已有静态输入契约。主图只增加运行引用；实际 shape、dtype、`requires_grad` 与采集上下文写入 `<项目文件名去掉 .json>-data/runs/<run-id>.json`。右侧“运行数据”选择静态图或某次运行，桌面端自动加载引用，浏览器可以手动选择快照。只采集输入元数据，不是完整的中间激活或梯度跟踪。

当前 SparseWorld 使用 `SparseWorld.tensor-trail.json` 与 `SparseWorld.tensor-trail-data/runs/batch2-input-20261110.json`。该快照来自 batch=2 的真实数据预处理结果，仅绑定 `img` 和 `kwargs.temporal_ego_states`，未运行模型前向、loss 或 backward。图的静态节点、位置、连线和边框色保持不变。

在 SparseWorld 的 `forward_backbone` 断点处，若需要重新记录这两个输入，可以使用以下方式。执行前先保存 Tensor Trail 的修改，采集后重新打开主图；每次使用新运行 ID：

```python
import sys
from datetime import datetime, timezone
from uuid import uuid4
sys.path.insert(0, "/home/vci-4/LK/SparseWorld/tensor-trail/python")
from tensor_trail_runtime import describe_input, register_runtime_snapshot

schema, _ = describe_input({
    "img": img,
    "kwargs": {"temporal_ego_states": kwargs["temporal_ego_states"]},
})
register_runtime_snapshot({
    "format": "tensor-trail.runtime-snapshot", "version": 1,
    "id": "run-" + uuid4().hex, "name": "forward_backbone inputs",
    "capturedAt": datetime.now(timezone.utc).isoformat(),
    "context": {"batch_size": int(img.shape[0]), "scope": "inputs only"},
    "bindings": [
        {"nodePath": ["img"], "nodeType": "Input", "value": schema["fields"]["img"]},
        {"nodePath": ["kwargs"], "nodeType": "ForwardInput", "value": schema["fields"]["kwargs"]},
    ],
}, "/home/vci-4/LK/SparseWorld/SparseWorld.tensor-trail.json")
```

`nodePath` 必须对应图中真实节点 ID，不能用显示名称替代。子图输入可用多段 ID 路径。采集器先完成不可变快照文件，再备份并更新主图引用；重复 ID 的不同数据会报错。分享单次运行可用“导出当前运行单文件”；分享全部运行应整体复制主图与快照目录。

## PLUTO 历史集成示例

先保存网页中的项目。使用已配置好的 `pluto_learn` 环境运行：

```bash
/home/vci-4/anaconda3/envs/pluto_learn/bin/python \
  /home/vci-4/LK/pluto_learn/pluto/script/export_tensor_trail_input.py \
  --project /home/vci-4/LK/pluto_learn/pluto.tensor-trail.json
```

完成后在 Tensor Trail 中点击“打开”，重新选择这个项目文件。当前浏览器内存中的图不会随磁盘变化自动更新。后续修改 batch size、模型超参数或数据配置后，可以再次执行命令采集。

更新工具也会把快照 `context.model_config` 中的顶层标量配置补入项目的 `hyperparameters`，在“模型超参数”标签页查看。以下划线开头的框架字段和嵌套对象不会导入。已有同名超参数保留，避免覆盖图中手动调整的值；再次采集只补充缺失项，已有项如需同步应在面板中明确修改。每个导入值记录采集时间来源。

该脚本复用 `pluto/run_cache_train.py` 的当前配置、模型构造、训练集 DataLoader、collate、设备转移及 `training_step`，通过模型的 forward 前置 hook 在 `PlanningModel.forward(data)` 边界采集，并立即停止。它不会运行模型主体、计算 loss、反向传播、调用优化器或写训练 checkpoint。

当前适配器支持训练入口的 `precision=32`、`CHECKPOINT=None` 配置；不支持的配置会明确报错，不会悄悄换成推理配置或其他设备。采集中的 `grad_enabled=True` 表示入口处启用了自动求导，不代表执行或验证了反向传播。输入 Tensor 的 `requires_grad=False` 不影响模型参数在实际训练中的梯度计算。

## 产物

- `pluto.tensor-trail.json`：新增缺失的根层 `data` 网络输入（`ForwardInput`），或保留已有静态 schema，仅新增当前运行引用。schema 使用 JSON 对象，兼容旧字符串。其他节点、连接、布局、名称、备注和变体保留；已有字段的轴注释在维数相同时保留到采集结果。
- `pluto.tensor-trail-data/runs/<run-id>.json`：独立运行快照，包含真实输入描述及其节点绑定。默认生成唯一 ID，也可传入 `--run-id`、`--run-name`。
- `pluto.tensor-trail.before-runtime-时间戳.json`：修改前的原始项目备份。
- `pluto/outputs/tensor_trail/data_snapshot.json`：采集元信息，含具体 shape、dtype、device、requires_grad、输入路径、模型配置、batch size、seed、场景 token 和采集范围。

采集器将 `requires_grad` 写入运行快照的 Tensor 描述 `autograd={requiresGrad,source:"runtime"}`，不写死在静态图中，供画布统一背景色和属性面板使用。它只读取元数据，不读取或保存梯度数值；未导出的中间激活不会被假定为 on。旧快照没有该字段时，浮点 Tensor 保持“未知”。

这些文件不包含 Tensor 的数值、模型权重或梯度数组。只记录一个真实 batch 的结构快照，agent 数、地图元素数和参考线数等可能随 batch 变化。

若项目中有多个可选输入，使用 `--node-id` 明确要更新的根层输入节点。目标可以是已有字典输入或网络输入，更新后统一使用 `ForwardInput` 承载字典；已有输入节点的 ID 和连线不会更换。打开的网页若有未保存内容，需要先保存，再采集并重新打开。

## 首次实际采集结果

使用 GPU `cuda:0`、batch size 2、seed 0，训练模式下采集到 8 个顶层字段、35 个 Tensor。主要字段如下：

| 字段 | shape | dtype |
| --- | --- | --- |
| `agent.position` | `[2,49,101,2]` | `float32` |
| `agent.valid_mask` | `[2,49,101]` | `bool` |
| `agent.target` | `[2,49,80,3]` | `float32` |
| `map.polygon_center` | `[2,58,3]` | `float32` |
| `map.valid_mask` | `[2,58,20]` | `bool` |
| `reference_line.position` | `[2,3,120,2]` | `float32` |
| `current_state` | `[2,7]` | `float32` |
| `cost_maps` | `[2,600,600,1]` | `float16` |

`agent.position` 的 101 是 21 帧历史加 80 帧未来；模型内部会读取或切出各自需要的部分。49 包含自车和最多 48 个周围 agent。此处的具体数值来自采集结果，而非手工输入的符号示例。

## 在自己的调试断点中导出

可在已有训练项目的 `forward` 入口、能访问真实 `data` 时调用：

```python
import sys
sys.path.insert(0, "/home/vci-4/LK/pluto_learn/tensor-trail/python")
from tensor_trail_runtime import export_input_snapshot

export_input_snapshot(data, "/tmp/data_snapshot.json", context={"source": "forward debugger"})
```

然后使用独立更新命令，将该快照写入保存的项目：

```bash
/home/vci-4/anaconda3/envs/pluto_learn/bin/python \
  /home/vci-4/LK/pluto_learn/tensor-trail/python/tensor_trail_runtime.py \
  --snapshot /tmp/data_snapshot.json \
  --project /home/vci-4/LK/pluto_learn/pluto.tensor-trail.json
```

这条命令仍兼容原 `tensor-trail.runtime-input` 采集文件，但现在会将其转换为独立、带节点绑定的 `tensor-trail.runtime-snapshot` 并注册引用，而不是把整份采集数据塞进主图。

此方法捕获的是当前调试进程中的变量；自动采集脚本则在独立进程中按当前配置读取一个真实训练 batch。两者都不是自动读取另一个进程的局部变量。

本步支持字典和 Tensor 字段。2026-11-10 起，字典可使用同层统一的字符串键或安全整数键；
整数键以 `keyType: "int"` 保存，元数据路径中的整数也保持其类型。
例如 `temporal_ego_states[0]` 不会变成字符串键查找或 Tensor 的 batch 索引。
同层混合键、布尔键、list、NumPy 数组等仍明确报错，不会静默丢弃。
SparseWorld 的完整 batch 因此还不能原样导入，应明确选择当前需要的字段或继续扩展适配器。
完整 forward 计算图、梯度流可视化、代码生成和自动图同步仍属于后续工作。
