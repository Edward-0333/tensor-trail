# 连线与模块吸附

2026-11-09 在 D5 之后修正自动分支布线，并增加拖动模块时的连线对齐。网页和 Windows 桌面使用同一套实现。

## 使用

- 同一输出端口连接多个目标时，自动布线一起计算干线。目标处于不同横向距离，也可共用一个折点位置；上下布局同样支持。端口相对、顺向且有足够空间时采用公共干线，回折或混合方向继续使用原来的直角路线。
- 拖动模块，使端口短线接近所连接端口的高度／横向位置，或已有手动线路的接入位置。在 **12 屏幕像素**内会吸附，出现虚线辅助线和“连线已对齐”提示。松手后模块停在对齐位置，连线随之接齐。
- 吸附后有 18 屏幕像素的释放范围，减少边缘抖动。**按住 Alt 暂停吸附**，可以自由微调。这里的“固定位置”是松手保存坐标，之后仍可拖动，不是永久锁住模块。
- 同源分支的平行线段靠近时可以吸附共用干线；现在拖动公共段也可带着整组分支并入另一条同源干线。不同数据来源、不同输出端口以及普通交叉不会被当作同一连接。
- 多选节点通过节点拖动时，采用统一位移，内部手动折点跟随预览和移动；组内连线不会反过来把整组选区吸回原位。节点位置与需要更新的路线在松手时一起提交，只占一步撤销。

已有手动折点不会在打开项目时被整体重排。移动相关模块后，附近可合并的手动线路会在松手时尝试合并；需要越过较大距离时，仍可直接拖动线段。连线文字位置和模块语义不变，Ctrl+S 保存到当前关联文件。

## 实现与验证

原先每条自动线单独选择端点中点，目标位置不同就产生多个平行干线；而模块拖动只保存节点坐标，缺少端口与线路的磁吸。此次分别增加同源自动干线规划和基于拖动开始时几何的对齐。已重合、没有改变路线的候选不再抢占合并判断，公共段的多个目标也统一选择同一个合并参考。

## 重叠线路漏画实心点的修复

2026-11-09 在用户项目的 `key_padding_mask` 五路分支中复现：控制点存在约 0.00002～0.016 个画布单位的残差，并生成极短的折返。原算法以 0.000001 为容差追踪共享前缀，因而在线条看似重合的位置提前判定分开。实际窗口中只有 3 个点挤在源头附近，中间横干线的分岔缺点。

新增 `routeNormalization.ts`，在同一物理输出的分支内统一不超过 0.02 个画布单位的坐标残差，并去除由此产生的微小折返。最大 2 倍画布缩放下相当于 0.04 屏幕像素，远小于拖动时的 12 像素吸附距离。实际端口坐标保持精确，原 JSON 和手动控制点不在打开时被改写；有意错开的路线、不同来源及不同端口继续独立。

线条去重、分岔实心点、高亮与共享段命中使用同一份清理后的路线。拖段合并也使用相同几何，并按实际线段重新定位活动区间，避免删掉微小折返后数组下标指向错误位置。计算按输出分组缓存，未改变的信号保留路线引用。

修复后的真实窗口在 4 个实际分岔处显示实心点，包括横干线中间两个原本漏掉的 T 形分支。最后一条线路的普通转角和其他信号的交叉不会画连接点。精简的五路实际坐标作为 `tests/fixtures/noisyMaskRoutes.json` 随编辑器测试保存，覆盖分岔、去重、高亮、共享段拖动、端口位置与缓存稳定性。

验证结果：51 个测试文件、894 项测试及网页／桌面生产构建通过；项目副本的修复前后 SVG、分岔坐标和截图保存在本机 `test-results/noisy-junctions/`。原项目保持不变，源代码恢复点为 `.publish/backups/junction-dots-20261109/`。

最终体验回归为三个进程 DPI 下的 66 项观察通过，原文件哈希不变、测试进程已退出，结果位于 `test-results/experience-verified-1794212874698/`。本机拖动帧间隔中位数约 13.3 ms；150% 样本记录到一条 59 ms 长任务，保留原始测量，不据此承诺完全无卡顿。

## 模块内移后手动线路凸出的修复

2026-11-09 修复单独移动一个端点时，手动线末端仍固定在旧位置的问题。原先只有两个端点一起移动时才平移手动折点；把目标模块往左拖过旧末端控制点，会先画到旧位置，再折返回输入口，造成线路穿过模块并在右侧凸出。

新增 `endpointRouting.ts`：根据拖动开始时的实际路线重新接入移动后的端口。末端同一直线上的冗余控制点会随线路缩短而移除；若模块越过最近折角，该接入段调整到端口外，并保持 24 个画布单位的出口。远处手动绕行保留，源端和上下端口也采用相同规则。吸附辅助线同时限制在相应端口外侧，避免继续指向模块另一侧的旧控制点。

拖动预览和松手提交共用同一份端点调整，预览不改变项目或历史，位置与路线仍一次撤销。Alt 仅关闭吸附，线路仍正常跟随端点。打开文件时不自动改写已有手动路线。

验证：52 个测试文件、903 项测试和网页／桌面构建通过；三个进程 DPI 的实际窗口检查增至 69 项，新增持有鼠标左键时检查线路与辅助线不超出输入口，并验证松手后的整组撤销、重做、保存和重开。截图位于 `test-results/experience-verified-1794213854603/endpoint-shortening-preview-*.png`。

还在完整用户项目副本中实际左移了 `static_objects_encoder`：输入线路最右坐标与输入口坐标一致，辅助线没有穿过模块，节点与路线一起撤销成功。证据位于 `test-results/endpoint-static-check/`，用户原文件 SHA-256 未变，测试进程已退出。恢复点位于 `.publish/backups/endpoint-wire-follow-20261109/`；本轮未提交或推送 Git。
