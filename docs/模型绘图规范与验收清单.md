# 模型绘图规范与验收清单

版本：1.0；更新：2026-11-17。

本规范将 SparseWorld 绘图中形成的方法提炼为通用流程，适用于其他模型的首次绘制、逐段展开和局部整理。不固定模型名称、输入数量、张量尺寸、设备或网络结构。

**目标：让图忠实表达指定配置下的代码数据流，再通过层级、分区和关联引用降低阅读成本。不能为了画面简洁而改变计算含义。**

规则强度：**必须**是语义与保存安全要求；**推荐**是可按任务调整的显示策略；**可选**是额外细节。跨分区少连线属于推荐策略，不是软件禁止跨区连接的限制。工作区另有明确绘图约定时，在任务记录中说明采用的显示策略。

本文定义工作流程与验收标准；API 参数以 [AI 操作指南](AI操作指南.md)、当前模块目录及 Schema 为准，交互细节见 [使用与扩展](使用与扩展.md)。不要把文档里的示例名称当成可以直接调用的算子。

## 1. 能力边界

当前 Tensor Trail 提供静态图编辑、形状与类型推导、来源分析、部分控制流表达和运行快照展示。外部 AI/脚本理解代码，通过 API 构建和修改图；软件并非自动理解任意 PyTorch 项目的完整导入器。

- 静态图不执行真实网络前向、反向或优化器更新；运行快照也不等于重新运行模型。
- API 校验只能检查其支持的结构和算子契约，不能代替源码对照，也不能证明某个预测有效。
- 本规范的验收包含 API 检查、源码复核和可视检查；并非每个条目都有现成的自动检查器。
- 对不支持的语义，保留明确的模块边界、输入输出契约及未展开说明，或按需扩展 Tensor Trail。不能用错误算子或恒等连接冒充已实现。

## 2. 开始前的任务契约

先填写以下信息。缺少的信息先从项目中核实；仍不能确定时记录为未知，不通过猜测补齐。

| 项目 | 必须记录的内容 |
| --- | --- |
| 代码依据 | 仓库、分支/提交或工作区版本、相关源码文件；存在未提交修改时以实际文件为准 |
| 绘制入口 | 类名、方法名、所在文件；可以是 `forward`、`forward_backbone` 或指定子方法 |
| 实际配置 | 配置路径、继承配置及命令行覆盖、实际实例化的子模块类型 |
| 执行上下文 | train/eval、预训练/微调、epoch、是否启用梯度、精度策略及设备；未知项单列 |
| 输入契约 | 本层真实形参、顺序、容器字段、各维含义；仅在确认后填写实际尺寸 |
| 输出契约 | 返回类型、字段/元素顺序，以及本次是否计划绘至返回值 |
| 绘制范围 | 本次层级路径、代码区段、所选条件分支、循环轮次和展开深度 |
| 图与快照 | 项目文件、活动快照及其采集条件；新建图还是修改已有图 |
| 保留范围 | 不动的节点、分区、手动线路、布局、变体和运行记录 |
| 验证目标 | 静态检查、源码对照、可视检查；是否另需真实运行核对 |

配置决定网络实例，实际源码决定运算；注释和论文用于解释，不能覆盖代码事实。历史运行快照只证明其对应配置和时刻，不能自动套用到新配置。

入口不是完整训练流程时，图名和说明必须写清范围。例如绘至 `forward_backbone` 返回，不代表 loss、backward 和参数更新也已绘制。

## 3. 标准绘制流程

| 步骤 | 执行动作 | 进入下一步的条件 |
| --- | --- | --- |
| 1. 核实 | 读取任务契约、配置、源码、已有图及相关操作指南，查询模块目录 | 确定本次真实执行路径与未知项 |
| 2. 建骨架 | 建立真实输入、模块调用及已确认的返回接口 | 父子端口对应；不新增伪形参或伪返回值 |
| 3. 补计算 | 沿源码增量展开实参准备、算子、属性读写与中间值 | 每个已绘步骤可对应源码或有明确的合并说明 |
| 4. 补控制流 | 表达条件、循环、状态更新和结果收集 | 执行次数、状态版本、轮次形状及参数共享含义正确 |
| 5. 核语义 | 检查 shape、dtype、device、梯度、输入来源及证据 | 推断与实测分开；未知不伪造为确定 |
| 6. 整布局 | 按职责分区、写短注释、本层评级、就近放置关联引用 | 不改变计算、形参数量或真实模块层级 |
| 7. 倒查返回 | 从 `return` 检查字典覆盖、列表追加、最终值及末尾引用 | 输出结构和最终版本与源码一致 |
| 8. 验收保存 | 检查诊断、可视效果和差异，基于最新版本应用并复查 | 不覆盖并发修改；报告已验证范围与遗留项 |

步骤 3-7 可按小批次重复。逐行学习时允许只补到某一行，但必须标明“草稿/部分展开”，不为了让图看起来完整而补造下游计算。

## 4. 代码与图的语义规则

### 4.1 输入和真实调用边界

- 本层输入对应真实形参，不把权重、buffer、`self` 属性或内部局部变量添加成新的 forward 输入。`self` 的模块上下文单独表达，不当作数据集输入。
- `kwargs`、字典或列表先作为原有输入表示，再按实际代码读取字段。关联副本只代表已有值，不能增加形参数量。
- 模块内部从形参 `Inlet` 开始；返回值通过对应 `Outlet` 回到调用方。父子端口名称、顺序、类型及容器结构必须对应。
- `module(expr1, expr2, ...)` 的实参表达式必须在调用侧显示。进入子模块后不重复执行这些准备操作。
- 直接写在当前方法中的操作留在当前层；需要视觉归类时优先用布局分区，不凭空发明源码不存在的函数调用。
- 可将真实复杂调用先画成未展开模块，记录实际类型、代码位置和输入输出契约；不得把未展开内部宣称为已完成。
- 输入不必集中在最左端。只有一个使用位置时可把真实输入直接放在使用点旁，不保留无意义的孤立副本。

例如源码：

```python
result = self.block(x.detach(), y.reshape(B, N, C))
```

调用方绘制 `x -> Detach` 和 `y -> Reshape`，再连到 `block` 的两个端口。`block` 内部从这两个已经准备好的形参开始。如果调用发生在循环里，这两步也仍在每轮循环内执行。

### 4.2 值、操作与状态不能混同

| 代码对象 | 绘图含义 | 不允许的替代 |
| --- | --- | --- |
| Tensor / NumPy 数组 / Python 标量 | 各自的值类型；记录形状或标量类型 | 把 NumPy 数组、设备或 Python int 都画成 Tensor |
| `nn.Parameter` | 注册的模型参数；可能冻结，也可能从 checkpoint 加载 | 当作每次 forward 新随机生成的输入 |
| 模块对象与 `.weight` | 模块引用与参数读取，必要时用 `GetParameter` | 当作 Embedding 索引查表或复制出新参数 |
| buffer | 注册的模块状态；依据代码读取和更新 | 自动当作可优化参数，或断言一定没有梯度 |
| 普通属性赋值/读取 | 属性写入/读取及其执行位置 | 偷换成 forward 形参或跨层的普通关联副本 |
| 同名变量重赋值 | 不同计算时刻的值；节点 ID/说明区分版本 | 因名字或 shape 相同就合并为同一值 |
| list/tuple/dict | 保留元素、字段与顺序的容器 | 未经 `stack/cat` 就画成一个整齐的大 Tensor |
| 关联副本 | 同层同一份逻辑值的显示引用 | 表示 `clone`、`repeat`、`detach` 或一次新计算 |

构造和随机初始化必须与 forward 分开标注。读取已有权重不代表它仍是随机值；checkpoint、训练和冻结状态要按实际上下文说明。参数经过 `repeat`、扩维或其他计算后的 Tensor，不因来源是参数就继续拥有参数注册身份。

属性多次赋值时应区分版本和分支。静态绑定版本只是消除歧义，不等于执行了条件或自动证明哪个版本最终生效。

### 4.3 条件与循环

- 条件推荐使用 `IfRegion` 虚线框，标题写真实条件，框内放对应操作。只绘某条路径时说明选中原因；未知条件不擅自选定结果。
- 循环外初始化、每轮计算、状态反馈、列表追加与循环后结果必须分开。首轮的 shape 不可冒充全部轮次的 shape。
- 用户需要在父画布观察实参准备时，用 `LoopRegion` 展开循环区域，实参准备和调用同在区域内；不能移到循环前，也不能另套流程封装隐藏它们。
- 独立遍历元素可使用 `ForEachTensor`；跨轮传状态时使用支持状态的 `ForLoop` 或 `WhileLoop`。选择前查询当前算子的限制，不强行表达不支持的动态次数、退出或 Python 副作用。
- `IfRegion/LoopRegion` 是显示范围，不执行 Python 条件或循环。范围框本身不能证明某条分支已运行或某个状态已更新。
- 循环反馈虚线依据声明的状态接口配对，不依据同名或同 shape 猜测；不添加普通计算图环来模拟回传。
- 一个循环体图不表示共享权重：重复调用同一个模块与访问 `layers[i]` 的不同实例必须区分，并记录各轮的参数/形状契约。
- 部分展开标明已绘代码、当前轮次和未绘内容；未知循环结果保留未知，不用恒等线或初始空列表假装最终输出。

### 4.4 形状、数值与元数据

- 关键 Tensor 标明 shape 和各轴含义；动态尺寸写符号或逐轮规格，不把示例 batch、序列长度或通道数硬编码为普遍事实。
- 区分标量 Tensor、单元素向量和 Python 标量。零维 Tensor 显示为“标量 Tensor（0-D）”，存储 shape 仍遵循 Schema，不为美观改成 `[1]`。
- `view/reshape/permute/flatten/expand/repeat` 按实际轴变化表达；广播不等于实际复制，`expand` 也不等于 `repeat`。
- 创建 Tensor 时区分数据来源与 dtype/device 参考。`new_zeros` 不读取参考 Tensor 的数值或继承其梯度；`new_tensor(data)` 的内容来自 `data`，不是点号前的参考 Tensor。
- 已明确的 dtype/device 推荐用紧凑 `DtypeConstant/DeviceConstant` 显示当前值，在说明中记录原表达式、证据和适用配置；不再画无助于理解的读取长线。未知时保留 `GetDtype/GetDevice`，不能默认 CUDA 或 float32。
- 切换设备、精度策略或输入配置时重核这些常量。不能仅根据是否存在 GPU、checkpoint 类型或全局 AMP 开关猜测每个中间 Tensor 的实际类型。
- `matmul`、逐元素乘法、索引、掩码、坐标变换等必须使用准确语义；不能用只保证输出 shape 相同的算子替换。
- 源码中的 sigmoid、log/log1p、sqrt、clamp、chunk、topk 可直接使用标准节点。对 Chunk 核对实际块数及末块长度；对 TopK 分别连接 values 和 indices，并核对源码中 k 与轴长的关系。

### 4.5 梯度、来源和输出身份相互独立

| 标识 | 表达什么 | 不表达什么 |
| --- | --- | --- |
| Tensor 统一背景 / `grad` 状态 | 已声明、推断或采集的 `requires_grad` 状态 | 已有 `.grad` 数值、一定连到 loss、一定被优化器更新 |
| 根层输入来源小标记 | 当前分析支持的原始输入依赖路径 | 梯度状态、真实融合质量、信息贡献大小 |
| Parameter / Buffer 身份 | 对应的注册对象身份 | 一定可训练或一定不求梯度 |
| 分区输出徽标 | 该值对某个布局分区外提供数据 | forward 最终返回值或新输出端口 |
| 自动加粗绿色返回边框 | 值原样进入本层真实返回结构 | 无梯度、不能再被使用或训练已经完成 |
| 分区星级 | 同一画布内的逻辑重要性 | 参数量、耗时、FLOPs、梯度大小 |

背景色由统一梯度主题管理，不为单个张量另造“随机/真实数据”背景色体系。未知梯度保留未知；有计算依赖也不意味着实际梯度必然非零。

只有根层真实输入按接口顺序赋予 `1..N` 来源编号。子模块 Inlet、关联副本、参数、局部常量不获得新编号；移动节点不应改变输入身份。来源按真实算子语义传播，不能沿所有线无差别合并。

shape/dtype/device 依赖不是数值特征融合；容器打包表示汇集已有值，不等于神经网络融合。索引、条件或掩码对结果的选择作用也应按支持的规则记录，不能一律视为无关。未支持的传播保留 `?`，没有编号不等于随机或没有梯度。

`detach` 截断其输出通往上游的梯度路径，但保留数值来源；其他分支仍可能回传。`clone` 不等于截断梯度。不得因输出 shape 不变而省略这类有语义影响的操作。后续参数化层也可能从无梯度输入产生需要梯度的输出。

### 4.6 可省略与不可省略

可按任务省略纯断言、防御性类型检查、调试计数、日志及当前路径已证实无效果的重复形状整理，在交付记录里注明省略依据。若异常处理或检查决定了实际计算分支，则不能当作无影响代码删去。

判断标准不只是“前后 shape 相同”。归一化、激活、坐标映射、detach、属性写入、原地修改、clone 的别名语义都可能在 shape 不变时产生重要影响。源码未改；图只减少不影响本次理解目标的展示，不能宣称所有配置下等价。

### 4.7 双模式绘图（1:1 源码精确模式 / 精简语义模式）

- 需要逐行核对时保留源码算子、端口及参数。已有图可用 `collapse_calculations` 将同范围内连通且可安全收缩的计算合并为 `CalculationGroup`，用 `summary` 说明职责，用 `formula` 记录表达式。双击进入核对，`expand_calculation` 恢复独立节点。
- 大图可用 `auto_simplify` 折叠张量整理和逐元素计算。核对折叠前后的返回规格、外部依赖、分区成员及输出标记。保留共享值的分支、神经网络层、排序选择及拼接边界。
- 直接按规格绘制时使用 `SemanticOp` 声明输入依赖及各个输出 Tensor 的规格。记录源码或设计依据、轴含义和梯度证据。交付时说明哪些步骤仅有规格，哪些步骤可展开至 1:1 源码。检查异构输出时逐端口核对 shape、dtype 和 requires_grad。

## 5. 布局与可读性

### 5.1 按职责分区，而不是另造模型层级

- `LayoutRegion` 是圆角浅色背景的布局区域，不是函数、网络层、条件或循环。分区不改变端口和数据流，不为分区添加 forward 输入。
- 名称概括完整职责，例如“特征提取与查询编码”；不要把包含预测或演化的整段代码仅命名为“图像处理”。注释用一两句短语说明“用什么，做什么，产生什么”，不重复标题。
- 新建图或用户要求整理的范围内，按职责组织分区；不要自动重排已有图中未授权整理的区域。
- 优先自动适配以便继续补图；自动模式应允许成员向外拖动时扩展，手动尺寸用于稳定布局。当前分区不互相嵌套，节点仅属于一个布局分区；控制范围框与布局分区分别管理。
- 普通算子采用紧凑名称、图标和必要参数；神经网络层、真实封装模块保留结构感，细节说明放检查器。不要为改图外观无谓增加新算子。
- 必须检查标题、注释、端口、节点和线路是否遮挡；不能只根据 SDK 默认尺寸判断最终界面效果。

### 5.2 关联引用减少长线

| 场景 | 推荐连线策略 |
| --- | --- |
| 超参数、尺寸、循环索引等局部参数 | 每个显示节点最多一个直接使用点；多处使用时用 `duplicate_linked` 就近引用 |
| 同一分区内的普通 Tensor | 保留直接数据流，不把每条线都改成副本 |
| 跨布局分区的值 | 推荐在使用方所在区域创建就近关联副本，尽量不留跨界长线 |
| forward 末尾只有容器打包/更新 | 在打包模块旁为各最终值放一对一引用 |
| 跨真实调用层级传值 | 使用模块端口或真实属性读写，不用同层关联功能跨越调用边界 |

主节点留在产生或定义位置，可以没有直接使用边；不必为了保留一个使用点而拉长线。不画主节点到副本的连线，不将副本改成独立常量。算子输出不能直接关联时，先连就近的值主节点，再创建副本。

关联必须指向同层同一份逻辑值，不按名称或尺寸认定相同，不跨越运算、索引、detach、条件选择或循环更新。副本不新增计算，也不暗示运行时复制内存。

分区输出在主节点处声明；副本同步显示来源分区的输出徽标，但不继承分区归属，不为显示徽标重复声明 `members/outputs`。同一中间值可以继续在本区计算，也可以同时导出给其他分区。

### 5.3 重要性星级

新增或整理分区时填写 `importance` 和简短的 `importance_note`，仅比较同一 `path`、同一节点内部的分区。

| 星级 | 本层相对职责参考 |
| --- | --- |
| 1 | 读取形状、初始化容器、原样整理返回等辅助 |
| 2 | 类型转换、维度重排、调度等准备工作 |
| 3 | 几何映射、状态整理等关键支撑 |
| 4 | 重要特征变换、交互或融合 |
| 5 | 本层的核心表征、推理、预测或状态演化 |

这些是参考而非固定映射。同一操作在不同层的职责不同，允许并列，不要求用满 1-5 星。不继承父分区评分、不汇总子层评分，不比较不同子图的星级。缺失或 `0` 表示未评级，低星不表示可删除。

## 6. 从返回值倒序核对

从当前方法的真实 `return` 开始，而不是从画布最右边开始。

1. 列出返回字段/元素及顺序，追踪各自最终使用的变量版本。
2. 展开末尾 dict/list/tuple 打包和字典更新，排除被覆盖的旧字段。
3. 遇到计算、索引、detach、条件选择、append 或循环更新时停止向前认定“同一最终值”；其输出可为最终值，输入不能因相邻就一起标为最终值。
4. 对仅剩引用或打包的路径，在打包处放关联副本，主节点保留在结果产生处。
5. 连接真实 Output/Outlet 后检查软件自动返回边框，不手工涂绿模拟结果。循环体的状态 Outlet 不等同于当前 forward 的返回值。

列表应核对长度、每个元素的 shape 和轮次；不同层输出的列表不能擅自 stack。循环后还有追加预测或覆盖字段时，循环刚结束的值不能提前冒充最终返回值。

## 7. API 编辑与保存协议

图的语义修改必须通过 API，不直接手改持久化项目 JSON。可生成 Recipe/Patch JSON，再交 API 构建与校验；不得为了满足图中的形状修改原模型实现。

1. 读取最新项目及运行快照引用，确认图路径和稳定节点 ID；不要以显示名称代替身份。
2. 查询当前模块目录和 Schema，确认端口、参数及算子能力。只在表达能力不足时扩展 Tensor Trail，并补对应的推导、传播和回归测试。
3. 分批调用 `patchModel(project, patch, {mode: 'draft', layout: 'preserve'})`。子图操作明确 `path`；不要对已有图重新 build 以替代增量修改。
4. 检查 `ok`、诊断严重度及路径；`project` 存在不代表校验成功。草稿允许缺失部分连接，但不能豁免已知形状错误、悬空端点或非法环路。
5. 用新旧项目差异确认只改了本次目标。保留其他节点位置、手动线路、分区、变体和快照；不执行未经请求的全图自动布局。
6. 应用前再次确认版本。画布 API 使用 `expectedRevision`，冲突时重新读取并重做 Patch；文件方式优先另存预览，在真正覆盖前重读并核对文件版本，不覆盖用户新修改。
7. SDK/CLI 不会自动更新已经打开的画布；报告实际保存位置和是否需要重新打开。静态图与运行快照继续分离，不把快照内容塞回主图或清空原引用。

API 形状示例，`project`、`patch` 由调用方提供；此代码不写文件：

```js
import { describeModules, getSchemas, patchModel, validateModel }
  from './packages/model-core/dist/tensor-trail-agent.js';

const catalog = describeModules(true);
const schemas = getSchemas();
const options = { mode: 'draft', layout: 'preserve' };
const changed = patchModel(project, patch, options);
if (!changed.ok) throw new Error(JSON.stringify(changed.diagnostics));
const checked = validateModel(changed.project, { mode: 'draft' });
// Review diagnostics and the project diff before applying or saving.
```

示例从 Tensor Trail 仓库根目录使用构建后的 SDK。活动运行快照未加载时，独立 SDK/CLI 只作静态检查并报告相应诊断；需要快照参与校验时，按 API 指南向两次调用提供同一有效 `runtimeSnapshot`。不能宣称这段代码已经完成并发保护、落盘或真实运行验证。

## 8. 验证证据与完成标准

### 8.1 每项结论说明依据

| 证据类别 | 可使用的表述 | 不能推导的结论 |
| --- | --- | --- |
| 源码/配置声明 | “由当前配置指定”“根据构造代码声明” | 本次实际运行已经观测到该值 |
| 静态推导 | “根据算子与输入规格推导” | 已经执行前向或 backward |
| 运行观测 | “在某配置、模式、轮次采集到” | 所有分支、所有样本或以后配置都相同 |
| 未知/不支持 | “尚未采集”“传播规则暂不支持” | 默认补成 false、空来源或固定数值 |

冻结与梯度要同时考虑参数声明和执行上下文；来源标签是静态依赖，不是实际有效信息量。运行数据与静态推断不一致时查配置、缓存、版本或推导规则，不能改标注掩盖冲突。

### 8.2 分开报告验收层次

| 验收层次 | 具体检查 | 当前工具/方式 |
| --- | --- | --- |
| 结构 | ID、端口、连接、子图边界、引用和图格式 | API 诊断 |
| 静态语义 | 已支持的 shape、dtype、梯度/来源传播；未知项说明 | API 及推导结果复核 |
| 源码忠实度 | 调用侧参数、条件循环、赋值版本、返回结构和覆盖范围 | 源码逐段对照 |
| 可视交互 | 分区、遮挡、长线、进入/返回子图和关联定位 | 实际编辑器检查 |
| 运行一致性 | 指定配置的真实输入及关键中间结果，与图中声明对照 | 原项目调试或有效运行记录；按任务需要执行 |

`draft` 的 `ok: true` 只表示可继续编辑，不等于完整、正确复现源码或可训练。范围完整时运行严格校验；如存在未解决的必需输入、输出或已知语义错误，不宣称该范围完整通过。可保留工具暂不支持的部分，但必须明确“部分展开”或“契约声明”，说明影响。

没有要求真实运行时可以交付“源码与静态校验完成，未做运行核对”。没有图形界面条件时报告“未做可视检查”，不能用静态检查代替这一结论。已记录的警告不必一律清零，但每条需说明原因和影响。

## 9. 验收清单

以下清单用于每次交付。`[x]` 只表示已实际检查；不适用项填写理由，未检查项保持 `[ ]` 并写入遗留问题。局部绘图只验收本次声明范围，不要求重新整理整个项目。

### A. 范围与接口

- [ ] 已记录源码版本、实际配置、入口方法及本次展开范围。
- [ ] train/eval、阶段、epoch、循环轮次和梯度上下文已核实或明确未知。
- [ ] 根层输入数量、顺序和容器契约正确；没有因副本或分区增加输入。
- [ ] 子图 Inlet/Outlet 与真实调用参数及返回值对应。
- [ ] 未展开部分、略去步骤和防御性代码的省略依据已有说明。

### B. 计算与控制流

- [ ] 实参创建、索引、reshape、detach 等在调用侧，子模块未重复计算。
- [ ] 模块、参数、buffer、属性和普通 Tensor 身份区分正确。
- [ ] 初始化不冒充每次 forward 执行，权重共享/独立实例关系正确。
- [ ] 同名重赋值、原地修改和属性多版本没有被错误合并。
- [ ] 条件框和循环框只表达范围，没有被误认为执行引擎。
- [ ] 循环初始化、每轮参数准备、状态更新、append 及循环后结果位置正确。
- [ ] 反馈只连接声明的循环状态；未用恒等线伪造未实现计算。
- [ ] 各轮 shape 与真实规则对应，没有把首轮契约用于全部轮次。

### C. 张量与证据

- [ ] 关键 shape、轴含义、标量和容器元素规格已核对。
- [ ] 广播、permute、reshape、matmul、索引等实际语义正确。
- [ ] dtype/device 有依据；配置改变时已复核显式常量。
- [ ] 元数据依赖没有误画成数值或特征融合。
- [ ] requires_grad、Parameter 身份、梯度路径和优化器更新未混为一谈。
- [ ] detach 保留来源、截断对应梯度路径；未知梯度和来源未被猜定。
- [ ] 来源编号只来自根层真实输入，副本与内部形参未新增编号。
- [ ] 声明、推导与运行观测可区分；活动快照与本次上下文匹配或已说明未加载。

### D. 分区与关联引用

- [ ] 分区按完整职责命名，短注释解释其工作，不制造新函数层级。
- [ ] 星级仅在本层比较，并有依据；未把低星当作可删代码。
- [ ] 布局分区归属、自动/手动尺寸及控制范围关系正确。
- [ ] 局部参数显示节点一对一连接使用点，多处使用采用同值关联引用。
- [ ] 按本次约定减少跨区与末尾打包长线，没有全局拆散普通 Tensor 数据流。
- [ ] 副本关联同一层同一版本的值，没有跨过运算、detach 或状态更新。
- [ ] 主节点留在定义处，副本不独立造值，不新增形参或主副连线。
- [ ] 分区输出徽标来自真实声明，副本显示继承标记但不错误继承归属。
- [ ] 紧凑算子、模块层级、标题、端口及线路可读；未破坏无关手动布局。

### E. 返回值

- [ ] 已从真实 return 倒查，返回字段、顺序和每个值的最终版本正确。
- [ ] 字典覆盖、循环追加及补充预测均已纳入最终结果判断。
- [ ] 不同 shape 的列表未被擅自合为一个 Tensor。
- [ ] 最终返回边框由真实路径自动判定，没有手工伪造或混同分区输出。
- [ ] 循环状态输出未误认成 forward 最终输出。

### F. 编辑安全与交付

- [ ] 使用当前 API/Schema 和明确的子图 path，未手改持久化图 JSON。
- [ ] API 错误已修复；警告、未知项和草稿状态已逐项说明。
- [ ] 写入前重读或检查 revision，未覆盖用户并发修改。
- [ ] 未改原模型以迎合图，保留无关节点、布局、手工路径、变体与快照。
- [ ] 已复读保存结果；明确文件与已打开画布是否同步。
- [ ] 已分别报告静态、源码、可视和运行验证结果，未执行的验证明确注明。
- [ ] 若新增算子能力，已补语义、形状/类型、梯度/来源、API/序列化及必要 UI 回归测试。
