# Tensor Trail 架构方案

## 1. 目标与范围

本项目暂名 Tensor Trail，面向阅读模型架构和开源项目后的学习过程。用户定义输入 Tensor，手动加入 CNN、RNN、Transformer 和维度操作，观察数据沿网络传播、每条连接上的形状变化以及参数不兼容的原因。后续可以将 Transformer 拆成注意力、归一化和前馈网络，再展开 Q/K/V、拆头、矩阵乘法等步骤。

典型案例：输入 [8,100,64] → Transformer → Permute → Conv1d → Permute → LSTM，得到序列输出 [8,100,32]。Transformer 外部形状保持不变，但内部可以追踪 [8,8,100,8] 的分头张量和 [8,8,100,100] 的注意力分数形状。

第一版聚焦形状与结构。分步动画表示依赖传播，不代表 GPU 执行时间或真实数值。训练、梯度、真实注意力权重、任意 PyTorch 项目自动导入列为后续扩展。

## 2. 技术选择

采用本地优先的 Web 应用：React + TypeScript + Vite，React Flow 负责画布交互，Zustand 管理编辑会话。第一版无需 Python、CUDA、账号或数据库。项目导出为 JSON，并自动保存到当前浏览器。首次需要安装依赖；完成构建后可以在本地运行。

核心引擎使用纯 TypeScript，不导入 React、React Flow 或 DOM API。React Flow Node 只是自有模型数据的显示适配。未来可以接入 Python/PyTorch 执行后端或桌面外壳，而不重写模型描述。

## 3. 分层与依赖

| 部分 | 职责 | 禁止承担的职责 |
| --- | --- | --- |
| core | 图、端口、TensorSpec、诊断、递归推导、序列化验证 | 依赖 UI 库、决定视觉外观 |
| modules | 注册定义、参数 schema、算子公式、组合子图 | 访问全局编辑状态、操作画布 |
| editor | 连接、拖拽、选择、属性编辑、历史、保存和加载 | 重复实现数学公式 |
| views | 节点卡片、Tensor 轴示意、端口输出、步骤说明 | 修改计算结果、伪造真实数值 |
| runtime（后续） | 前向计算、数值采样、PyTorch 对照验证 | 将显示状态作为计算依据 |

数据流为：编辑模型 → 推导结果 → 渲染节点、连线标签、检查说明。修改节点位置不改变参数。第一版采用全图推导，易于保证正确；下游增量缓存、Web Worker、图虚拟化在性能数据证明需要时增加。

## 4. 核心协议

### 模块定义与实例

定义包含稳定 type、版本、分类、参数 schema、端口、说明以及 infer 函数。schema 驱动属性面板。实例包含 id、type、definitionVersion、名称、参数、位置和可选具体子图。多个实例各自保留参数与子图，不共享可变状态。JSON 只保存数据，不保存可执行脚本。

### 图与端口

采用有向无环图，支持分支、汇合、多输入和多输出。边明确记录起点节点/端口及终点节点/端口。单个输入端口最多一条入边；Add/Concat 通过多个命名端口接收输入。LSTM 独立提供 out、hidden、cell，GRU/RNN 提供 out、hidden。

第一版把循环网络作为封装算子，时间递归由序列语义表达，画布本身不允许回环。交互连接与导入检查端点、端口、重复输入和环路。

### TensorSpec 与诊断

TensorSpec 保存 shape、axes、dtype。例如 shape=[8,100,64]，axes=[batch,sequence,feature]，dtype=float32。Permute 同时更新尺寸和轴含义。

尺寸可为正整数或 B、T 等简单符号；输出允许表达式。第一版不实现通用符号方程求解，无法证明的约束显示待验证信息。未知类型、缺失输入或上游错误不能伪装成成功的输入透传。

节点结果包含各输出端口的 TensorSpec、说明、诊断及可选子图结果。诊断区分参数错误、输入缺失、上游阻断和符号约束。节点内错误向外层组合模块传播，并保留内部发生位置。

### 保存协议

项目包含 schemaVersion、名称、根图、变体库；实例保留模块定义版本。导入验证数据结构、支持版本、类型、唯一标识、端口和嵌套深度，未来通过显式迁移升级。位置和子图保存在项目中；选择、缩放、播放步骤和推导缓存不作为模型语义。

## 5. Transformer 与分层展开

Transformer、Attention、FFN 使用真实子图，通过 Inlet/Outlet 映射内外端口。引擎递归推导子图，汇总输出与诊断。折叠和展开使用同一份模型，只改变当前查看路径。首版采用双击进入和面包屑返回，避免所有层级同时铺满画布。

Transformer 首版使用 batch-first [B,T,D]，支持 Pre-Norm/Post-Norm、LayerNorm/RMSNorm、GELU/ReLU/SiLU 和标准 FFN/SwiGLU。SelfAttention 展开为 Q/K/V 投影、SplitHeads、K 转置、MatMul、Scale、可选因果 Mask、Softmax、MatMul、MergeHeads 和输出投影。

标准组合模块的父层参数修改后重新生成内部结构。一旦手动编辑内部结构，该实例标记为自定义，禁用父层结构重建参数，避免覆盖用户修改；内部节点仍可逐个编辑。布局拖动与改名不触发数学结构自定义。

保存变体会生成独立名称和完整子图快照，加入用户模块库；再次添加时深拷贝，各实例独立。变体随项目导出，不依赖另一台设备事先安装模板。模板更新不会悄悄改变已有实例。

因果 Mask 在形状模式只表达遮挡语义，不生成真实分数。首版为自注意力；交叉注意力、独立 Q/K/V 接口、GQA/MQA、RoPE、KV Cache 留有算子和子图扩展位置，但未实现的能力不能只换名称冒充完成。

## 6. 可视化扩展

基础视图展示卡片、边上形状、端口结果和 Tensor 轴。按模块类型注册专属视图，无法匹配则使用通用 Tensor 视图。组件只读消费模块和结果，不重复推导。

后续可增加矩阵切片、卷积窗口、拆头动画、真实注意力热力图、变体并排比较。数值数据应携带来源（真实运行/教学样例）、图版本、节点路径、端口和采样信息。高维张量通过 batch/head/切片选择展示。

第一版按拓扑顺序分步高亮依赖，每步展示该节点的输入输出与说明；该顺序用于教学，不声明实际并行执行顺序和耗时。

## 7. PyTorch 后端路线

后续引入统一运行接口：输入版本化图及输入配置，输出节点路径到张量元数据/数值引用的映射。可以通过本地 HTTP 服务接入。数值模式显式触发，避免每次修改参数都运行模型。

先用于独立核验 Linear、Conv、RNN、Transformer 的形状，再提供前向数值。torch.fx 等机制可辅助代码导入，但数据依赖控制流和自定义算子不保证自动支持，应保留未覆盖节点和解释。首版无需后端运行即可使用全部形状功能。

## 8. 测试策略与里程碑

核心测试依据手算结果与公开算子契约，覆盖卷积长度、轴排列、Reshape 守恒、多端口路由、残差兼容、头数整除、子图一致性、变体隔离、非法输入和保存恢复。浏览器检查添加模块、参数修改、错误提示、两层展开、变体保存重用、JSON 往返与刷新恢复。生产构建执行 TypeScript 检查。

1. 第一版：核心协议和算子、递归组合、画布、属性面板、形状视图、变体库、本地保存、核心与浏览器验证。
2. 第二阶段：更多 Transformer 变体算子、教学动画、多切片视图、自定义子图接口编辑。
3. 第三阶段：PyTorch 数值适配、框架对照、部分模型导入。
4. 根据需求扩展大型图性能与桌面打包。
