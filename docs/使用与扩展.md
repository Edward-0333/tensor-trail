# 使用与扩展

## 启动

在项目根目录双击 start.cmd，会启动本地服务并打开浏览器。原 app/start.cmd 仍转到新入口。也可在根目录执行 `npm run dev:web -- --port 5178`，访问终端显示的地址。首次换设备使用 Node 24 LTS，在根目录执行 `npm ci`。启动和检查命令见 [应用说明](../apps/web/README.md)。

宽窗口采用模块库、画布、检查器三栏。宽度不超过 850px 时使用“模块库 / 画布 / 参数与形状”切换面板，适合 Codex 侧栏预览。图较大时使用左下角缩放和 Fit View，或在小地图中移动视口。

## 工作台界面

2026-10-19 的界面改版参考 TensorBloom 的编辑器布局：默认深色画布、紧凑工具栏、分类色标、属性侧栏和底部数据流面板。右上角日月按钮切换深浅主题，主题偏好保存在当前浏览器地址；两枚侧栏按钮可隐藏模块库与属性面板。切换示例或进入子图后，画布在节点测量完成时自动适应视口。

- 左侧类别可折叠，默认展开输入输出与 Transformer。点击搜索框或在非编辑状态按 `/` 搜索模块；侧栏隐藏时快捷键会重新打开它。
- 类别颜色在模块库、节点顶部和小地图保持一致：Transformer 为橙色、卷积为紫色、循环网络为青色、输入输出为绿色。名称与文字同时保留，不依赖颜色区分类别。
- 未选中模块时，右侧显示当前层级的节点数、连接数、组合模块数与模块分布；选中后显示参数和 Tensor 观察。
- 底部数据流卡片显示每一步的输出形状，继续支持单步、高亮播放和恢复全图。浏览器窗口较窄时，各面板通过顶部标签切换。

## 普通操作节点

后续新增或调整节点时，采用以下展示约定，不因底层实现是一个模块就使用大卡片：

- 普通算子、属性读取、类型转换和张量创建优先使用紧凑节点，仅保留操作名称、必要的小图标和关键参数；详细代码、说明和诊断放在右侧检查器或悬浮提示中。
- 封装模型、可进入的子图和神经网络层保留能够表达结构的模块样式；张量值、输入边界与控制区域继续使用各自的专用样式。
- 多输入操作保留可辨认的端口。数据与 dtype/device 元数据不得混为一条特征输入，端口方向、选择、错误和单步状态不能因精简界面而丢失。

例如 `.device` / `.dtype` 使用同类属性读取节点，`astype` 显示转换图标与目标类型；`ArrayToTensor` 按创建方式显示小型创建图标和 `new_tensor()` / `torch.tensor()`，保留 `in`、`device` 以及适用时的 `dtype` 端口，不显示通用模块大图标、标题栏或轴示意。此调整仅影响展示，不改变已有图的节点位置、连接关系与推导规则。

## 第一次使用

顶部“新建项目”创建空白画布并保留“我的变体”，可用撤销返回上一项目。数据流观察默认收起，点击底部“数据流观察”展开；逐步观察会自动展开。

输入/输出 Tensor 的名称可双击直接修改，Enter 保存、Esc 取消。节点留白已压缩，轴含义显示在各节点下方；选中输入 Tensor 后，右侧每个轴都有独立的含义输入框。修改输入形状时轴输入框数量同步调整，下游按算子规则传播轴含义。

右侧“张量配色”页签统一管理 `grad:on`、`grad:off`、`grad:?` 三类 Tensor 背景，影响整个项目及所有子图，随 JSON 保存并支持撤销。节点保留文字角标，不只依赖颜色。逐节点自定义颜色改为“Tensor 边框”；旧 `tensorColor` 会在打开时迁移为 `tensorBorderColor`，不改变节点位置或连线。选中和错误提示优先于自定义边框。容器与 Python 整数不使用梯度背景。

`grad:on/off` 表示 `requires_grad=True/False`，不是实际梯度数值、是否连接最终 loss 或是否已经 backward。Tensor 属性面板和字典字段可标注状态；来源区分运行时采集、手工标注与静态推导。未标注的浮点 Tensor 默认为未知，整数/bool Tensor 依据 dtype 为 off。仅值传递保留原状态；已知 off 可通过 View 等无参数形状操作推导。参数化层、未知算子及需要 grad-mode 上下文的 on 传播不猜测，显示未知，需采集或显式标注。改变运行模式后应重新核实标注。

保存格式：项目级 `tensorPalette={on,off,unknown}`；单个节点的 `tensorBorderColor` 控制边框，`tensorAutograd={requiresGrad,source}` 标注 out Tensor。字典 schema 的 Tensor 描述支持同结构的 `autograd`。所有颜色均为六位十六进制；不包含梯度数值或 Tensor 内容。

本层的最终返回值使用加粗绿色边框。软件从 Output/Outlet 倒查，只穿过值引用、dict/list/tuple 打包和字典更新；遇到实际计算、索引、detach、条件选择或列表追加就停止。字典更新被覆盖的旧字段不标记，循环体的状态输出也不冒充 forward 的最终结果。主节点和关联副本共享该身份，连线改变后自动重算，不写入项目 JSON。悬停边框可查看解释；绿色只表示“原样进入本层返回结构”，不表示无梯度，也不排除其他分支使用。梯度背景、来源标签保持不变，选中外框和错误红边仍然生效；手动边框色保留，退出最终输出身份后恢复。

末尾只有容器打包时，可以在打包模块附近为各结果创建关联副本，缩短跨图连线；结果主节点留在计算处，不必再连一条长线。与局部参数一样，共享同一份值，不是复制数值或重复运行计算。

1. 打开默认“走进 Transformer”。点击 Input，编辑 shape，例如 `4, 50, 64`；axes 填写 `batch, sequence, feature`。轴名称数量要与形状维数一致，也可留空自动命名。
2. 点击 Transformer，在检查器修改 heads、d_ff、归一化位置、归一化类型及前馈结构。输入特征需匹配 d_model，d_model 必须能被 heads 整除。
3. 双击 Transformer，进入真实子图；再双击 Self-Attention，观察 Q/K/V、拆头、分数矩阵和合头。面包屑可返回上层。
4. 右上“探索示例”切换到 Transformer → CNN → LSTM。两个 Permute 分别转换序列格式与卷积的 channels-first 格式。
5. 点击 LSTM 后切换 out、hidden、cell 标签，查看不同端口的形状和轴含义。

## 添加、连接和删除

- 在画布空白处按住左键拖动进行框选，矩形碰到节点即选中；按住中键拖动平移画布。
- 左键拖动节点可移动节点；框选后可整组拖动，所有位置一起保存，一次撤销即可恢复。
- 选中单个或框选多个模块后按 Ctrl+C / Ctrl+V（Mac 可用 Cmd+C / Cmd+V）复制粘贴。会复制所选模块、完整子图及它们之间的连接；与外部模块的连接不复制。每次粘贴生成独立 ID 并错开位置，支持跨项目粘贴和一次撤销。同画布仅局部参数默认关联原值；其他节点默认独立复制，多处使用时直接从原节点连线。需要共享值时，在右侧点击“创建关联副本”；普通复制不会自动共享原张量。完整子图或已有完整关联组的内部结构保持可移植副本。编辑文本时保留浏览器原有复制粘贴行为。子图 Inlet/Outlet 普通复制会新建独立接口；显式创建关联副本则复用已有接口。
- 左侧模块库与“我的变体”仅显示名称，单击条目不会添加模块。
- 从左侧模块库或“我的变体”拖到画布，在松开鼠标的位置添加独立模块。拖入时保持当前缩放和平移，不自动连线；之后拖动端口连接。进入子图后拖入会添加到当前子图，同样支持文件保存和一次撤销。
- 需要接 hidden/cell 等其他端口时，拖动相应输出圆点到目标输入圆点。修改已有连接前先点击连线并按 Delete 或 Backspace 删除。
- 选中模块后，右侧“端口布局”可分别设置输入和输出的位置，支持左、右、上、下，或恢复自动布局。多路端口会沿所选边排开，输入输出选在同一边时也会分开排列。位置设置随项目保存和导出，支持撤销，不改变形状推导。
- 每个输入端口最多一条入边。Add、Mul、MatMul 用 a、b 两个输入；Cat / Stack 可在右侧选择 1–16 个输入，按 a、b、c… 的顺序拼接或堆叠。禁止环路，错误会出现在底部消息区。
- 点击连线后，拖动出现的圆形控制点即可手动绕线；双击连线可增加控制点，双击控制点可删除。选中连线时的“恢复自动”可清除手动路线。拖动过程中按 Esc 可取消，每次拖动可一次撤销；控制点随项目和变体保存。模块位置和连接关系保持原有设置，移动模块或调整端口后，线的两端会继续跟随对应端口。
- 点击模块后使用检查器删除按钮，或选中模块后按 Delete。子图 Inlet/Outlet 边界节点受到保护，不可从界面删除或改端口名。
- 支持撤销和重做，保留最多 40 次编辑历史；撤销后返回模型总览。刷新不恢复撤销历史。
- “下一步”和“逐步观察”按拓扑顺序高亮模块。点击显示全部按钮恢复全图。步骤用于理解依赖，不表示真实执行耗时。

## 布局分区

布局分区（`LayoutRegion`）用圆角矩形和浅色填充整理同一画布，不是模型封装，也不改变计算、梯度或输入来源。

1. 框选模块后点击工具栏“新建分区”，选中的模块会移入新分区；未选择模块时创建空分区。也可从模块库拖入“布局分区”。
2. 选中模块，在属性“所属分区”中选择目标分区；支持对当前多选模块一起设置。或点击分区标题，在分区属性中搜索、勾选成员。成员加入时移到分区内部，已有成员不重排。
3. 成员只能在所属分区内拖动，多选移动同样受边界约束。要移出，先在模块属性点击“解除分区归属”或选择“无分区（解除归属）”，也可从分区成员列表取消勾选。
4. 拖动分区标题可整体移动分区及成员。点击标题后拖动四角或边缘调整大小，也可输入宽高；手动缩小不能裁掉内部模块。
5. “自动适配大小”收紧到成员范围，后续按成员实际尺寸自动适配；手动调整后切换到手动尺寸。新增成员或模块内容变大时仍会扩展必要空间，不把成员裁到外面。分区颜色可在属性中修改。

归属、颜色、位置与尺寸随项目保存，支持撤销/重做。删除分区只解除归属，不删除成员；复制分区会复制成员并重建归属，单独复制模块不会自动继承所属分区。移动分区时内部手工线路整体平移，跨分区连线因端点移动重新走线。

当前每个节点只能属于一个同层分区，不支持分区嵌套。`if/for` 虚线框仍表示代码范围，不作为布局成员；其中的普通节点可以独立归入布局分区。打开旧图不会自动生成分区或移动已有模块。

“解除分区归属”只取消移动边界，不影响值关联或 forward 输入数量。“解除值关联”会把共享值变成独立值；对 forward 输入执行时，输入数量会增加 1，界面会说明影响并要求确认。不要为了移出分区而解除值关联。

选中分区后可在属性填写“分区注释”，用一句话概括职责（最多 240 字符，离开输入框时提交）。注释显示在标题下方；过长时省略，悬停查看全文，不挤动内部模块。

在分区属性的“分区输出”列表中勾选成员，或选中成员后勾选“标记为分区输出”，节点上方会显示“分区输出 · 分区名称”。这是显式的布局角色，不增加 forward 输出端口、不改变梯度，也不同于自动判定的最终返回值绿色边框。分区外的关联副本不会自动继承此标记。移出/删除成员会清除其分区输出角色，复制整个分区会保留注释并重建输出引用；均支持保存和撤销。

桌面交互回归使用独立临时项目和配置，不操作当前用户窗口。先执行 `npm run build:agent`、`npm run build:desktop`，再执行 `env -u ELECTRON_RUN_AS_NODE node_modules/electron/dist/electron scripts/desktop-layout-regions.cjs`（需要桌面显示环境）。

## 层级导航

顶部“上一层级”按钮固定在路径栏左侧，不随长路径滚动；每次返回一级，根画布禁用。
路径导航不再重复显示自动附加的 `forward()`，保留模块名、循环体及初始化等说明。
进入深层或调整窗口大小后，路径栏自动滚动到当前层；长名称悬停可查看全文，仍可点击任意上层直接跳转。
导航只切换视图，不修改模型、循环迭代选择、运行快照或撤销记录，也不重命名图文件中的节点。

## Forward 输入

当前层级的真实输入带有 `IN · 序号/总数` 标签；面包屑下方的“已绘制输入”导航条列出名称，点击可定位并选中节点，不移动节点、不修改图文件。根层统计输入 Tensor、ForwardInput 和 DictionaryInput；子层只统计真实 Inlet，与父模块端口顺序一致。关联副本、内部张量、局部参数、模块参数和 buffer 不计入，列表或字典整体只算一个输入。编号按图中接口顺序生成，不随拖动位置变化。“已绘制”不代表代码参数已全部录入；循环体或函数子图的标签表示本层接口，而不是主模型的 forward 参数。输入身份标签独立于梯度背景和自定义边框颜色。

“输入输出”分类中的 **Forward输入**（类型 `ForwardInput`）是一个带细边框、居中文字的矩形。除 `IN` 身份标签外，画布默认只显示名称，双击文字可修改，Enter 提交、Shift+Enter 换行、Esc 取消，也可在右侧修改模块名称；不显示形状、字典/列表类型、图标或额外的内容框。

节点继续支持默认或自定义边框色、端口方向、拖动、复制粘贴、删除、撤销重做和文件保存。容器不按梯度状态填充背景。右侧“备注”可选，用来保留额外说明，备注不显示在画布上。原字典和列表输入已合并；打开旧项目时自动转换，保留自定义名称、原说明、位置、颜色（迁移为边框色）和连线。

Forward 输入不要求填写形状，可通过 Identity、输出节点和自定义子图边界传递。当前不自动提取其中的 Tensor；张量算子仍需连接独立的 Tensor 输入。AI 配方示例见 `examples/structured-input.recipe.json`。

## Q/K/V 三输入注意力

从 Transformer 分类拖入 **Q/K/V Attention**，分别连接 `q`、`k`、`v` 三个输入端口。模块类型为 `MultiheadAttention`，原有单输入 Self-Attention 和 Transformer Block 继续使用同一份输入生成 Q/K/V。

三路输入使用 batch-first 格式：Q 为 `[B,Tq,d_model]`，K 为 `[B,Tk,kdim]`，V 为 `[B,Tk,vdim]`。三者 batch 和浮点 dtype 必须一致，K/V 序列长度必须相同；Q 的序列长度可以不同。`kdim`、`vdim` 默认 0，表示跟随 `d_model`，也可分别设置输入特征宽度。`d_model` 必须能被 `heads` 整除。

端口接收投影前的查询、键和值输入，模块内部各有一层 Linear，将三路特征投影到 `d_model` 后拆头。输出为 `[B,Tq,d_model]`，分数矩阵为 `[B,heads,Tq,Tk]`。三个端口连接同一份 Tensor 可做自注意力；Q 接目标序列、K/V 接另一条序列可做交叉注意力。

双击模块可查看三个边界输入、Q/K/V 投影、拆头、矩阵乘法、Softmax、合头及输出投影；右侧提供内部形状快照。`causal` 默认关闭，开启时标记按 query/key 索引屏蔽未来位置的因果遮挡，矩形分数矩阵也保持形状；当前不执行数值计算，也不处理 KV Cache 的位置偏移或外部 mask。

AI 配方示例位于 `examples/cross-attention.recipe.json`：Q `[2,3,64]`、K `[2,5,32]`、V `[2,5,48]`，输出 `[2,3,64]`。可用 CLI build 后在网页导入，也可将配方粘贴到“AI 构建”。

## Cat 切片与计算模块

分支运算中的 **Cat**（`Concat`）与 **Stack** 都采用紧凑节点，输入数量可在右侧选择 1–16；沿端口 a、b、c… 的顺序处理。Cat 沿已有轴拼接，Stack 插入新轴；其余尺寸必须兼容，混合数据类型按支持的 PyTorch 类型提升规则推导。缩减前先断开将被移除的输入。旧 Cat 仍默认两路输入。

数学运算中提供 `Cos`、`Sin` 和局部整数乘法；维度操作中的 `View` 支持整数端口指定尺寸。具体用法及 PLUTO 的 T 重绑定示例见[特征拼接与动态形状](特征拼接与动态形状.md)。

维度操作中的 **切片 Slice** 默认执行 `[..., :2]`。参数 dim 选择轴（-1 为最后一轴），start/stop 可留空或填写负数边界，stop 不包含在结果中，step 为正整数。边界会裁剪到有效范围，空区间的轴长度为 0；符号长度无法确定时会给出警告。

基础层中的 **计算模块 Compute** 是顺序运算容器，右侧可添加、删除和上下移动步骤。初始为 `[..., :2]`，目前可组合切片、`~` 取反和 `any()`；节点内直接显示各个运算块。最多 16 步，后续新操作通过白名单规则扩展，不能粘贴任意代码执行。

基础层的 **Tanh** 对应 `torch.tanh`，支持 float16、bfloat16、float32、float64 输入，保持形状和轴含义，并显示双曲正切示意曲线。当前不模拟整数输入的 dtype 提升，遇到整数或 bool 会明确报错。SparseWorld 的尺度映射可在 Tanh 后连接“函数”模块，公式设为 `(points_scale + 1) / 2 * (1.5 - 0.8) + 0.8`；画布仅推导形状，范围说明不代表已采集数值或验证梯度。

- `~` 接受 bool 或 int64，保持形状；浮点输入会明确报错。输入 Tensor 新增 bool 类型。
- `any()` 输出 bool，轴留空表示全部轴归约，输出为标量 `[]`；也可指定轴，并选择是否保留长度为 1 的轴。
- 此处只推导形状、轴含义和 dtype，不执行真实张量数值运算，因此不需要 PyTorch。示例见 `examples/calculation.recipe.json`，其中切片、Cat、取反和按轴 any 组合得到 `[2,3]` 的 bool 输出。

## 创建 Transformer 变体

快捷方式：选择 Transformer，修改 norm 为 RMSNorm、ffn 为 SwiGLU，给变体命名，然后点击“保存为我的变体”。左侧会出现新的模块条目，可重复拖入画布。

进一步修改：进入 Transformer 内部，选择归一化或其他普通算子，使用“替换算子”选择端口标识兼容的模块，也可添加、删除和重新连接内部节点。保存当前组合即可生成新模板。

手动编辑内部结构后，父层会标记“已自定义”，父层结构重建参数禁用，防止修改一个 heads 值覆盖整个内部编辑。此时进入子图逐个修改算子即可。移动节点、改显示名称不锁定父模块。

变体为带固定参数的子图快照。每次添加都会创建独立实例，修改一个实例不会影响模板或其他实例。第一版没有把自定义变体的内部参数重新提升为父层可编辑参数；需要改变内部特征宽度时，应修改相应的 Linear、Norm、Attention 等节点并保持约束一致。

SwiGLU 固定使用 SiLU 门控；此时 Standard FFN 的 activation 选择不改变 SwiGLU 的内部激活。Transformer 采用 batch-first，首版没有 dropout 数值执行或训练模式切换。

## 静态图与运行快照

2026-11-10 起采用第一阶段拆分：主图仍是一个 JSON，运行数据存到旁边的独立文件。没有引入数据库，也没有把所有子图拆成文件。

```text
SparseWorld.tensor-trail.json                 # 结构、布局、配色、静态输入契约、快照引用
SparseWorld.tensor-trail-data/
  runs/batch2-input-20261110.json              # 一次运行的输入元数据
```

主图 `runtime.snapshots` 保存 `{id,name,file}` 引用，`file` 是相对于主图所在目录的路径；`runtime.active` 记录当前选择。快照含版本、采集时间、上下文及 `bindings`；绑定由节点 ID 路径定位 `Input` / `ForwardInput` / `DictionaryInput`，保存 shape、dtype、axes 和可选 `autograd`，不含张量数值或权重。

右侧“运行数据”可选择“仅静态图”或某次运行。桌面端自动读取主图已声明的本地快照；浏览器或不支持关联读取的打开方式需手动选择快照 JSON。缺失文件、错误 ID 或节点绑定变化会明确报错，不会把静态形状冒充本次观测。此阶段只覆盖输入节点，其余节点继续按已有规则静态推导，不是完整运行轨迹。

普通保存仅修改主图，不重写快照。Python 采集器先完成快照文件再发布主图引用，同一运行 ID 不能覆盖为不同数据；采集前应先保存桌面编辑，采集后重新打开项目。已有静态输入契约不会被新 batch 覆盖。

“导出当前运行单文件”生成含当前快照 `runtime.embedded` 的便携副本，只保留这一运行的引用；无须复制外部目录。导出不改变原文件关联。选择静态图时导出的副本不含运行数据。分享所有运行时则应整体复制主图和快照目录。

CLI/独立 Agent 校验不会自行读取旁边的文件。校验具体运行时请使用便携副本；校验纯静态结构时可导出静态图副本。否则会明确提示运行快照未加载。

字典 `params.schema` 现在保存对象，兼容旧 JSON 字符串。编辑校验直接处理对象，不再先整图 stringify 再 parse；文件脏状态检查按不可变 Project 版本复用序列化结果。撤销仍保留完整 Project 快照，尚未改成增量补丁或磁盘数据库。

### 新增基础算子的最小例子

例如创建 packages/model-core/src/modules/square.ts，提供一个形状保持算子定义：

```ts
import type { ModuleDefinition } from '../core/types';

export const square: ModuleDefinition = {
  type: 'Square',
  label: 'Square',
  category: '基础层',
  description: '逐元素平方；形状模式仅推导尺寸。',
  fields: [],
  inputs: [{ id: 'in', label: '输入' }],
  outputs: [{ id: 'out', label: '输出' }],
  infer: ({ in: x }) => ({
    outputs: { out: { ...x, shape: [...x.shape], axes: [...x.axes] } },
    notes: ['逐元素平方保持形状；这里不计算张量数值。'],
  }),
};
```

随后在 modules/index.ts 导入 square 并执行 `registry.register(square)`。它会自动出现在基础层分类，端口和参数面板也由定义产生。规则接收 TensorSpec，不接收画布节点；多输出算子返回多个命名端口。

算子参数通过 fields 声明 number/text/select/boolean；普通整数参数可指定 min。数学约束使用显式检查，失败抛出可读错误；符号维度不能证明的约束通过 warnings 返回。不要在遇到错误时假定输出等于输入。

### 新增组合模块

参考 composites.ts 的 FFN：声明 composite=true 和 build(params)，创建 Inlet、内部节点、Outlet 及端口连接。通过 registry.create 实例化基础算子和已有组合模块。build 只负责构造图，形状推导由通用引擎递归处理。使用稳定的内部节点 ID，便于视图定位；不同子图中的相同 ID 由完整路径区分。

适合先用组合实现归一化位置、激活和门控差异。RoPE、GQA 等涉及新语义时，应添加专门规则，再纳入组合；不能仅给已有 Attention 换名称。

### 新增可视化效果

details.tsx 已注册 Transformer、SelfAttention 和 MultiheadAttention 的内部形状快照。新 React 组件接收 `DetailProps`，包含 node 和 result；读取 `result.outputs` 或 `result.child` 后展示。调用 `registerDetailView('模块类型', 组件)` 加入详情视图。不要在视图中重新实现 shape 公式。

未来加入动画时，保持动画进度与模型参数分离。真实热力图需要后端实际张量或明确标注的教学数据；纯形状模式不能提供真实注意力权重。高维数组应通过 batch/head/切片选择展示。

## AI 构建与自动化入口

### 根层输入来源编号

顶部“输入来源”开关启用当前项目的静态来源追踪。只有根层真实输入（Input、ForwardInput、DictionaryInput）自动获得 `1、2、3…` 来源编号；顺序与根层“已绘制输入”一致，不按节点位置排序。使用节点 ID 识别来源，改名或拖动不会改变对应关系；增删或重排根层输入后统一重新编号。关联副本不占新编号，子模块 Inlet、参数、buffer、常量和局部变量也不创建编号。

画布沿用小标签形状，编号使用不同的填充色；悬停显示对应根层输入名称，右侧属性面板显示全局编号图例。多来源数值运算显示去重后的多个标签，例如 `[1] [3]`。来源编号不占用梯度背景或自定义边框，也不同于 `IN · 1/4` 这种本层接口序号。无需选择“图像/自车”等业务类别，可适配任意输入名称、数据类型和输入个数。

传播的是根输入的数值依赖。字典取值、视图操作、激活、跨层传参、属性读写、`Detach` 保留相关编号；`Add`、`Mul`、`MatMul` 等数值操作合并来源。shape、dtype、device 不算数值融合，`NewZeros`、`ZerosLike`、`Arange` 不继承参考张量的来源编号。容器仅汇总内部元素的来源，不能据此声称元素已融合；读取元素后只追溯该元素。已知无根输入依赖的参数、常量不显示编号，初始化历史及模型状态仍可在详情中查看；没有编号不等于“随机”或“无梯度”。

例如 SparseWorld 根层为 `1=img`、`2=img_metas`、`3=kwargs`。`kwargs['temporal_ego_states']`、`ego_feat`、`points_scale` 及缩放后的 `init_points` 均传播 `3`；视觉特征传播 `1`；缩放前的 `init_points` 和初始零值 `query_feat` 不携带输入编号。未来真正连接两条数值路径后才显示组合编号，不根据模块名或端口个数猜测融合。

来源分析按算子语义执行。尚未支持的算子显示中性 `?`，已知来源可与 `?` 并列，不从复制的形状规格猜测来源。已展开函数依据真实内部连接传播；`ForEachTensor` 逐元素追踪；`WhileLoop` 沿各自状态的反馈路径进行来源集合的定点分析，不把所有输入统一合并给所有输出。编号只是静态路径，不衡量实际有效信息量或融合效果，不能排除零权重/掩码使某条路径无效。

While 的来源分析合并初始状态与后续可能迭代的依赖，包含动态索引、写入值及分支条件；未使用的捕获输入不传播。已知零次迭代原样返回，已知一次只分析一轮，上界为符号时保留零次执行的可能。多次迭代的编号是可能依赖的保守集合，不代表某一轮真实执行的精确来源；只改变来源信息，不改变 shape、梯度、实际数值或画布布局。最多分析 32 轮来源集合，稳定后提前停止；不支持的算子继续保留 `?`，未稳定时保留已知来源并显示 `?` 和警告。循环内部仍只展示一个符号模板，不展开 1040 份。模型状态可能含历史更新或 checkpoint 信息，不据此认定其历史与训练数据无关。

JSON 只需保存开关，编号、名称和派生标签推导时计算，不写入每个节点。运行快照仍提供 shape/梯度观察值，不伪造运行时来源证据。API 沿用草稿与布局保留机制：

```json
{
  "patchVersion": 1,
  "operations": [
    { "op": "set_lineage_enabled", "enabled": true }
  ]
}
```

旧图的 `informationSource` 业务类别仅兼容读取，不参与编号，也不能覆盖自动传播。已移除手工类别下拉框；旧 API 操作 `set_information_source` 仅接受 `source: null` 清除历史声明，不允许手工创建来源。

### Buffer 与行归一化

`BufferSource` 表示构造阶段已经注册、随后被读取的模块缓冲区。形状可连接 d0–d7 整数接口；dtype、初值、persistent 和 requires_grad 是静态声明。绿色边框与 `BUFFER` 标签表示注册身份，背景仍按梯度状态统一管理。它不是数据集输入、forward 形参、Tensor 子类或 Parameter；浮点 buffer 也可以有梯度，但优化器不会将它自动视为参数。

节点代码同时展示构造声明和读取位置，out 表示读取的 buffer 引用，不是 register_buffer 的返回值。构造初值不等于当前数值：checkpoint 和手动更新都可能覆盖它；静态图不在每次 forward 重置 buffer，也不声称采集了实际计数。dtype 转换后新建的临时 Tensor 不继承注册身份；无变化的 Cast 保留同一引用的身份。

`Divide` 是逐元素广播真除法，支持实数类型提升；整数真除法使用节点记录的默认浮点 dtype，不是整除。它不自动添加 epsilon/clamp 或证明分母非零。SparseWorld 的 `num_stamps_all.float()` → `sum(dim=-1,keepdim=True)` → `/` 将 `[Q,7] / [Q,1]` 广播成 `[Q,7]`，只重新绑定局部变量，不修改原 int64 buffer。这一段位于 `ind_stamps_all` 缓存未建立的条件分支，图中仅展示该分支的计算。

### 设备元数据 GetDevice

`GetDevice` 对应 `tensor.device`：输入为 Tensor，输出为独立的 `DeviceSpec`，不是 Tensor，也没有 shape、dtype 或 requires_grad。`tensor_name` 只标注表达式，真实来源由输入连线决定。静态图显示 `maps.device`，不假定实际设备是 CUDA/CPU，不伪造运行时设备观测。

`DeviceVariable` 为设备值命名，显示中性的 `DEVICE` 小标签，不使用 Tensor 梯度背景色或 grad 标记；支持 `duplicate_linked` 关联副本。设备值连线自动显示为灰色虚线，普通 Tensor 和整数尺寸连线保持实线。子模块 Inlet/Outlet 也可以传递 Device。

新建 `Arange` 和 `OnesScaled` 默认 `device_source=device`，只接受 `device` 接口上的 Device 元数据，不再接受参考 Tensor。例如 `maps → GetDevice → maps.device → Arange.device`，另由 `num_points` 接入 `end`。旧版未设置 `device_source` 的节点仍按原 `in` Tensor 接口解释，保存/重开不强制改写；迁移时通过草稿 API 添加 GetDevice、替换连线并设置 `device_source=device`。`tensor_legacy` 仅用于旧图兼容。`NewZeros` 的 dtype/device 参考语义本次保持不变。

### 匹配前的初始化与排序

`OnesScaled` 合并表示 `torch.ones(size, device=device) * value`，用于 `inds` 的全 -1 初始化。尺寸可连接 d0–d7；Device 接口只决定设备，不继承 dtype、数值或梯度。默认浮点类型按节点的 `default_dtype` 静态声明，不把源码改解释为自动推断整数 dtype 的 `torch.full`。`Arange` 对应整数 `torch.arange(end, device=device)`，输出 `[end]`、int64，生成规则为 0 到 end-1。两者创建的普通 Tensor 均为 grad:off，不是 Parameter 或 buffer，静态画布不分配真实数组；Device 元数据本身不标记 grad:off。

`SortRowsByMax` 是 `reweight(maps)` 的专用函数块：忽略末尾 `trailing_columns` 列，求各行最大分数，使用 `torch.sort` 的索引重排整行。默认忽略最后的原始 query 编号列，降序排序；不改变 shape/dtype，但改变行顺序。编号随行保留，输入不被原地修改；并列分数不保证稳定次序，画布不会伪造排序结果。

SparseWorld 的准备阶段分成独立的 `inds [Q]` 初始化支路和 `maps [Q,7]` → 拼接编号列 `[Q,1]` → `[Q,8]` → 排序支路。第 8 列不是时间帧；concat 将 int64 编号提升为 float32。Concat 可设置 `axis_name=score_or_id` 仅覆盖输出拼接轴的含义，避免沿用 time 标签误认为 8 个时间帧；留空保留原行为。只绘制 utils.py:103–107 时跳过 assert，不提前绘制后续 while、num_inds 配额使用或函数返回。相关子图保持草稿状态，Size 和局部参数关联副本让 Q 随输入变化，不硬编码 1040；设备依赖与数值依赖在接口和代码说明中区分。

### 解码器的数据准备与多层返回

投影矩阵准备应直接画在解码器 `forward` 当前层，不人为增加函数调用或返回值。`BatchMetaArray` 对应按样本提取字段并执行 `np.asarray(...).astype(...)`，输出独立的 NumPy 数组规格，不是 Tensor，也不显示梯度状态。其 shape 是针对不透明元数据的声明，数据配置变化时需要核对；不会额外画出源码不存在的 B/TN 计算步骤。

逐步绘制时，将 `BatchMetaArray.operation` 设为 `asarray`，它只提取字段并构造数组；再连接独立 `NumpyAstype(dtype=float32)` 表示 `.astype(np.float32)`。原 dtype 未采集时使用 `source_dtype=unknown`，不猜测为 float64；类型转换后才明确显示 float32。旧图未指定 operation 时仍合并执行 astype，保持兼容。NumpyAstype 不改变 shape 和来源编号，输出仍不是 Tensor。

`ArrayToTensor(mode=tensor)` 使用数组的 dtype；`mode=new_tensor` 则通过 `GetDtype` 与 `GetDevice` 接收参考张量的类型和设备。两条元数据连线均使用灰色虚线，不传播参考张量的数值来源。新 Tensor 默认不求梯度，数值来源仅继承数组。随后直接连接 `Unsqueeze`、`ExpandAs`、`MatMul`，不再用“准备投影矩阵”的假调用层包裹这些操作。旧的合并模板 `BatchMetaTensor` 保留兼容，但逐行展示应使用分开的数组与 Tensor 转换步骤。

`Detach` 保留 Tensor 的 shape、dtype 和数值来源编号，但输出 `requires_grad=False`，不继承 Parameter/Buffer 注册身份。后续带参数的网络层仍可能产生可求导输出，不能把这一状态延伸到整个解码器。`ExpandAs` 只使用 `like` 的形状广播单例轴，不传播 `like` 的数值来源或 dtype，也不等价于 `repeat` 复制。

`Detach` 的画布样式为紧凑图标加 `detach()`，不显示通用网络卡片的标题栏、底栏和重复轴标签。图标上方的实线表示数据继续传递，下方的反向虚线遇到竖线停止，表示梯度被截断；不是切断数据流。完整名称和共享存储等语义在悬停提示与属性面板中查看，输入输出端口及既有节点位置不变。

`BooleanIndexAxis` 使用“保留高亮记录”的筛选图标、`按轴筛选` 和 `dim` 标签，不再仅显示 `x[:, mask]`。端口标出 `x` 与 `mask`，表示沿指定轴按顺序保留 True 对应的整项，其他轴不变；不是逐元素乘法置零或连续切片。启用数量契约时，灰色虚线接入“契约”端口，节点和连线上显示数量及其声明性质；它只辅助形状推导，不是 Python 索引的第三个数据参数，也不是实测计数。图标不表达实际 mask 值。普通整数运算和尺寸连线仍保持原样，原端口 ID 与项目数据不变。

`BatchMetaTensor` 描述收集 `list[dict]` 某字段并转为 Tensor 的边界，设备必须由独立 `GetDevice` 接入。由于输入元数据不透明，shape、轴含义和 dtype 是显式声明的契约，不是运行时采集或已验证的真实矩阵尺寸。用于 `new_tensor` 调用时，需要核对配置 dtype 与接收张量一致；其来源编号仅来自元数据，不来自尺寸/设备参考。

`OPUSDecoderLayerContract` 是可逐步展开的网络层接口模板，检查 5 个输入与相机、分组、特征维数等约束，输出 `[B,Q,D]`、`[B,Q,P,num_classes]`、`[B,Q,P,3]`。它不运行网络，不伪造梯度状态；输入的数值依赖与参数来源按明确的 OPUS 契约传播。将它放入带 Inlet/Outlet 的子模块后，可用 API 逐步替换为真实内部算子。

SparseWorld 图的解码器用 `ForEachTensor` 展示四个尺度的重排；循环体显式绘制 `GC // G`、`B*T*G` 和两种布局的 permute/reshape，中间 Tensor 可随“当前迭代”切换查看。CUDA 的 channel-last 路径与 else 的 channel-first 路径分别用虚线条件框表示；当前图按 `MSMV_CUDA=True`，仅 CUDA 结果接到公共 contiguous/append，else 结果作为未选用的备用路径展示。条件框不执行 Python 或自动切换连线；更换后端需同步修改收集入口和下游层的 layout。只有局部整数尺寸使用关联副本，普通 Tensor 保留真实数据连线。

六个解码层使用通用 `ForLoop` 带状态循环，进入循环体后切换 0-5 轮，查看 `query_points` 的点数逐层变化为 `1,4,16,24,32,48`。图中只保留一个循环体，并不表示六层共享权重；`decoder_layers[i]` 内的接口契约按 i 选择本层规格。每轮开始对坐标做 `Detach`，特征继续传递；两个紧凑 `append()` 把本层分类与未 detach 的预测坐标收集到列表。列表初始值在循环外建立，最终返回 query_feat 和两个六元素列表。`query_points` 是内部循环状态，不额外接到 Decoder 的 return；未使用的 `pred_stamps=[]` 不作为输出。`DUMP.stage_count=i` 仅记录在索引说明中，不伪造特征运算。

`ForLoop` 与 `ForEachTensor` 不同：前者会把 Outlet 反馈给下一轮同名状态 Inlet，允许形状变化、列表增长；后者各轮独立。最多静态推导 16 轮，不执行 Python，不支持 break/continue 或动态循环次数。其余输入为固定捕获值。列表最多 256 个 Tensor，元素保留自己的梯度和来源编号；循环结构本身不决定权重是否共享。

进入 `ForLoop` 循环体时，同名状态的 Outlet 与 Inlet 自动用带箭头的虚线连接，并标注“变量名 → 下一轮”。依据循环声明的 `states` 和接口 `port` 匹配，不比较显示名称、数值或 shape；固定输入和索引不画回传线。虚线不是新数据线，不参与形状/梯度/来源推导，不创建计算图环路。普通子模块和独立迭代的 `ForEachTensor` 不因端口同名而产生回传线。

点击虚线可选中并高亮，拖动水平段上下移动、拖动竖直段左右移动，也可以沿线拖动文字；两端仍连接原来的状态接口。`Alt` 拖动暂不吸附，`Esc` 取消当前拖动，松开鼠标后可用 `Ctrl+Z` / `Ctrl+Shift+Z` 撤销和重做。选中后的“恢复自动走线”会清除该线的手动布局。布局随 `Ctrl+S` 保存到 ForLoop 节点的 `loopFeedbackRoutes`，不加入 `edges`；仅点击选中不会修改文件。移动节点时端点自动跟随，“适配全图”包含手动回传线；各轮共用同一套布局。

Decoder 的 `decoder_layer` 已用 `OPUSDecoderLayer` 展开 forward 主流程，不再只有整体接口占位。
可查看 flatten、位置编码、位置相加、采样、AdaptiveMixing、norm1、自注意力、norm2、FFN、norm3，以及分类和坐标回归两个分支。
位置编码、分类 MLP、回归 MLP 和 refine_points 都可继续进入内部；MLP 使用真实 Linear/LayerNorm/ReLU 顺序，
refine_points 展示 reshape、decode_points、沿点轴求中心、加位移和 encode_points。
采样、混合、自注意力与 MMCV FFN 暂以有输入校验的封装表示，内部后续展开；FFN 契约明确包含默认残差及 Dropout。
它们不运行 Python 或产生真实特征值。当前配置回归位移乘 `0.5`，分类输出是 logits，预测坐标没有附加 sigmoid/clamp。
首次迭代位置编码只带自车状态来源 3，采样后出现图像/元数据来源 1、2；后续轮次继承上一层已融合的信息。
切换循环轮次时，MLP 输入/输出维数与预测点数同步变化，采样特征始终为 `[B,Q,G,T*num_points,D/G]`。

### 清理非有限数值与列表返回

`TensorSequenceGet` 在画布上使用“序列中选出一个元素”的小图标和紧凑的 `[索引]`，例如 `[-1]`；不再显示通用网络大卡片、底栏和重复轴标签。它读取 list/tuple 中一个完整 Tensor，不是对 Tensor 的某个轴切片。悬停可见完整节点名称和说明，选中后仍在属性面板编辑索引、查看输出 shape/dtype/梯度；端口、连线及已有位置保持不变。

`DictionaryGet` 使用同样紧凑的“字典键值对 → 取出值”图标和字段路径，例如 `["query_feat"]`。嵌套路径保留逐级方括号，整数键 `[0]` 与字符串键 `["0"]` 分开显示。长路径省略显示，悬停查看完整路径；在属性面板修改字段。这里只读取字段，不复制或融合数据，不增加标题栏或底栏。

`DictionaryPack` 可将 Tensor、Tensor list/tuple、子字典和 None 放入同一个字典。组装不进行 stack、concat 或特征融合；每个字段及列表元素保留自己的 shape、dtype、梯度标注和来源编号。字典来源只是成员来源的汇总。右侧字典树支持展开列表查看各元素，`DictionaryGet` 取出列表后可继续用 `TensorSequenceGet` 读取元素。输入 schema、保存重开和运行快照也支持字典内的 Tensor 序列；输入编辑器对序列结构只读，可经 API 修改。

`DictionaryPack` 在画布上使用“多路字段写入花括号”的紧凑图标与 `dict()`，不显示通用卡片的标题栏、底栏或重复的字典摘要。输入端口保留字段名，输出显示 `dict`（端口 ID 仍为 `out`）；长字段名省略显示，悬停端口可查看完整名称。节点尺寸随端口数量与方向调整，不改字段顺序、连线或项目中的位置。

SparseWorld 的 OPUSHead 将缩放后的 `init_points`、`cls_scores`、`refine_pts`、`query_feat` 按源码键名组装为 `init_points`、`all_cls_scores`、`all_refine_pts`、`query_feat`，从一个接口返回；外层 `outs` 是这个字典，不是 Tensor。`init_points` 仍为 Transformer 前的初始坐标，不是最后一层预测坐标。

`NanToNum` 是紧凑的单输入算子，对应默认参数的 `torch.nan_to_num(x)`：NaN 替换为 0，正负无穷替换为该浮点类型的最大/最小有限值，已有有限值不变。保留 shape、dtype 和输入来源；不是归一化、类型转换或 detach。这里只推导规格，不执行真实数值清理，也不凭空断定运行时梯度状态。

SparseWorld 的 `OPUSTransformer` 在 decoder 后分别用两个 `ForEachTensor` 表示 `cls_scores`、`refine_pts` 的列表推导式。每轮只清理一个 Tensor，按原序收集到新的空列表，六层不同点数的形状分别保留。进入循环体可切换元素查看 `nan_to_num`；`query_feat` 不经过清理，与两个结果列表一起从三个返回接口输出。

### 按参考 Tensor 创建零张量

`NewZeros` 对应 `Tensor.new_zeros(size)`：`in` 仅提供 dtype/device，目标形状由 `shape` 的字面尺寸或 `d0`–`d7` 整数接口决定。它不继承参考 Tensor 的形状、数值或 requires_grad，也不会把梯度传回参考 Tensor。默认 `requires_grad=False`，因此输出显示静态推导的 `grad:off`；可显式开启，但整数/bool dtype 不允许开启梯度。输出不是 Parameter。

SparseWorld 的 `query_feat = init_points.new_zeros(B,Q,self.embed_dims)` 使用缩放后的 `init_points` 作为参考，尺寸分别连接 B、Q、self.embed_dims，当前为 `[2,1040,256]`。这是创建独立的全零查询特征，不是从三维坐标提取 256 维特征。设备仅按算子语义继承，静态图不分配内存或推测实际设备。`Zeros` 的 dtype 单独指定，`ZerosLike` 保持参考形状，不能替代此语义。

### 模块属性读写

`SetAttribute`（SET）接收一个普通 Tensor，将其绑定到模块属性；没有 Tensor 输出端口。`GetAttribute`（GET）没有形参输入，从对应 SET 读取同一 Tensor 的规格和梯度标注。它们用橙色圆角边框及 SET/GET 标记显示，背景仍跟随全局梯度配色；不是 Parameter，也不新增 forward 形参。

两者使用相同的 `owner` 和 `name`：`owner` 是从根图定位所属模块的节点 ID JSON 数组，如 `["pts_bbox_head"]`，`[]` 表示根模型；`name` 是直接属性名，如 `points_scale`。输入路径不执行 Python 表达式。属性面板可定位对应读写节点。

推导引擎会安排写入先于读取，包括跨层隐式依赖，并检查循环。每次推导重新建立属性绑定，不沿用上一次运行的值；更改上游后 GET 随之更新，写入失败则读取失败，不生成独立占位 Tensor。当前每个属性仅允许一个写入点，不支持在 ForEach 内写属性或注册/替换 Parameter；循环内可以读取外部已写入的属性。这是静态规格分析，不连接实际 Python 对象或执行训练。

API 可直接添加上述节点。迁移旧辅助输入时，使用同批 `replace_node` 将 Inlet 改成 GET，并删除父图上的旧输入连线；校验完整事务，若留下失效端口则拒绝。`replace_node` 保留节点 ID、默认位置及显式端口布局/边框，重新构造类型与参数；不自动保留梯度注释或关联副本。存在关联副本时需先解除或移除，不改变 `remove_node` 对边界的保护。

### 模块引用与读取参数

`EmbeddingModule` 表示构造 `nn.Embedding` 并注册权重，输出非 Tensor 的模块引用；`EmbeddingXYZModuleInit` 进一步展示 SparseWorld 的坐标列初始化。它们属于构造阶段，不会在每次 forward 中重新执行。旧图的 `EmbeddingWeight` / `EmbeddingXYZInit` 继续直接输出权重，保持兼容。

使用通用 `GetParameter`（读取参数，`name=weight` 或 `bias`）从模块引用取得已有 `nn.Parameter`。它对应属性访问，不是查表、乘法、clone、detach 或重新初始化。其他网络可先用 `ModuleReference` 声明模块路径、类型及直接参数表，再连接 `GetParameter`。这些都是静态规格，不连接真实 Python 对象或执行代码。

模块引用在画布上用虚线边框显示变量名，不再显示 `Module · nn.Embedding` 等类型文字；连线也隐藏模块类型，详细类型和参数表仍保留在属性面板。模块引用没有张量形状或梯度标记。参数值显示 `Parameter` 标签、默认蓝色边框，背景仍由统一的 requires_grad 配色管理。扩维、repeat 等派生结果不继承 Parameter 身份；梯度状态未知时仍显示未知，不把参数身份等同于梯度。

`ModuleParameterState` 只标记参数原地初始化已经完成，输出同一个模块引用；不是替换参数或重新注册参数。`ValueVariable` 可以显示模块引用，并通过 `duplicate_linked` 创建关联副本减少长连线。添加节点、修改参数、连接和调整边框均可使用草稿 API，并指定 `layout: "preserve"` 保留已有布局。
