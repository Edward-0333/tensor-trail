# Tensor Trail 标准绘图风格与程序设计规范

> **基准样板**：自 `2026-11-26` 起，Tensor Trail 后续的**画图风格**与**软件程序设计/扩展**统一以 `TemporalSelfAttention + LN` 子图定型的样式与工程原则作为长期标准。本文档与 [模型绘图规范与验收清单](模型绘图规范与验收清单.md)、[AI 操作指南](AI操作指南.md)、[架构方案](架构方案.md) 配套使用；如与早期历史记录存在冲突，以本文档为准。

---

## 一、核心原则总览

1. **忠实源码，零黑盒凑合**：每个实质计算步骤用真实算子与关键张量展开；绝不以大段纯文字 `SemanticOp` 或 AI 生成配图敷衍核心算法。
2. **PyTorch 自带算子缺失必新建原生模块**：源码调用 PyTorch 内置层或函数式算子（如 `F.grid_sample`、`torch.clamp`、`torch.topk`、`nn.GroupNorm` 等）而当前注册表未收录时，**必须新建原生 Tensor Trail 模块**并补全推导、图标、文档与回归测试，严禁长期用 `SemanticOp` 或拼凑形状的错误算子顶替。
3. **参数化软件能力优先于 AI 生图**：张量的 3D/4D 几何体积、尺寸、颜色、深度模式、轴名、算子图标卡、端口布局与输入拆分均须沉淀为软件原生 API（Recipe/Patch Schema）和桌面端实时可调面板，避免每次依赖 AI 重新生图。
4. **三层清晰的视觉层级**：数据流中**关键张量（3D/4D 几何卡）**、**核心网络层/数学算子（紧凑图标卡与圆形汇合徽章）**、**纯形状整理胶水链（连线上竖直 `↓` 堆叠胶囊）**各司其职，主次分明。
5. **模块输入严格 1 对 1 关联拆分**：模块输入多处复用时，按目标拆分为多份左上角带 `IN` 标识的关联副本，每份只连一个下游模块，消除一对多分叉与跨图虚线。

## 二、标准绘图风格规范（以 `TemporalSelfAttention + LN` 为样板）

### 2.1 模块输入 1 对 1 关联拆分规则（`IN` 副本）

- **适用对象**：当前画布的任意真实模块输入——子图内的 `Inlet` 或顶层的 `Input` / `ForwardInput`。
- **强制规则**：
  1. 只要某输入被当前层下游多个模块使用，就按目标使用点**拆分为多份同源关联副本**（CLI 使用 `duplicate_linked` / `valueSource`，界面可在检查器一键点击「按目标拆分为 N 份 IN (1对1)」触发 `splitInputFanout`）。
  2. **不增加外层输入端口数**：关联副本与主输入共享同一逻辑输入身份，`levelInputs()` 不重复计数。
  3. **左上角统一标注 `IN`**：主输入与其关联副本左上角均显示 `IN` 身份徽标（如 `IN · 3/3`）。
  4. **严格 1 对 1 输出连线**：每份输入卡片的输出端**只连接下游一个目标模块**（`out-degree === 1`），不进行一对多分叉，也不再使用跨图虚线或 `anchor` 锚点边替代模块输入复用。
  5. **就近摆放**：每份 `IN` 副本直接放在其目标使用模块旁（例如残差支路的 `query · 轨迹查询 (兼 identity)` 副本直接放在末尾残差 `+` 旁），避免横穿整张画布的长线。

### 2.2 统一单层 3D/4D 几何张量卡片

关键中间张量（`TensorVariable`）以及输入/输出端口采用统一单层几何张量卡片（`tensorVisual.mode = 'block'`，无多层嵌套边框）：

| 张量秩 | 几何表达规则 | 说明 |
| --- | --- | --- |
| 1D `[W]` | 单根水平细条 | 显示宽度轴名与尺寸 |
| 2D `[H, W]` | 单张平面薄板 | 显示高、宽轴名与尺寸 |
| 3D `[Z, H, W]` | 单个 3D 立方体积 | `Z ≤ 4` 或沿 `Z` 拼接时默认分层切片（`slices`）；`Z > 4` 或符号维默认连续实心深棱柱（`solid`） |
| 4D `[N, Z, H, W]` | **水平展开多个 3D 体积** + 底部外轴括号 | `N = 1, 2, 3` 逐个绘制；`N ≥ 4` 或符号维绘制首尾两个体积加 `···`，括号标明外轴名与尺寸（如 `q×head 16`、`queue 2`） |
| 5D / 6D+ | 末 4 维按 4D 渲染，更早维度（`shape.slice(0, -4)`）标在左上/上方轴标签 | 避免强行投影 5D/6D 几何体造成视觉混乱 |

**张量卡片硬性红线**：
- 张量卡片**只展示当前张量本身的状态与几何形状**（标题、shape、dtype、grad 状态、几何体、轴名与简短 caption）。
- **禁止**把计算步骤、公式流程或 AI 生图塞进张量卡片内部。
- 颜色语义通过 `tone`（`auto / blue / violet / teal / amber / rose / slate`）或 `#RRGGBB` 区分数据流支路（如查询/值特征用蓝色、偏移/位置用紫/琥珀色、权重用玫红色、采样/输出特征用青绿色），所有参数均通过 `set_node_tensor_visual` API 写入并可在检查器实时微调。

### 2.3 三类计算节点的视觉分层

| 节点类别 | 典型算子 | 推荐 `presentation` | 画面表现 |
| --- | --- | --- | --- |
| **有参数网络层 / 核心数学算子** | `Linear`、`LayerNorm`、`RMSNorm`、`Normalize`、`Conv1d/2d`、`Softmax`、`GridSample`、`FFN`、注意力/循环层、激活函数 | **`compact`**（紧凑图标卡） | **必须保持为独立可见卡片**，展示专属 SVG 图标 + 短规格（如 `Linear 256→256`、`GridSample · bilinear`、`LN(256)`）。**严禁折叠到连线上**。多输入紧凑层卡（如 `GridSample`）必须常显端口标签（`in` / `grid` / `out`）。 |
| **二元算术与拼接汇合点** | `Add (+)`、`Mul (×)`、`Subtract (−)`、`Divide (÷)`、`MatMul`、`Concat (‖)`、`Stack (⊞)` | **`compact`**（圆形汇合徽章） | `44×44` 圆形徽章，直观标明汇聚操作；`Concat` / `Stack` 同时标注 `dim`。 |
| **纯张量整理 / 视图胶水链** | `Reshape`、`View`、`Permute`、`Unsqueeze`、`Squeeze`、`Repeat`、`Flatten`、`Detach`、极简一元标量映射（如 `2x − 1`、`÷ [W=8, H=32]`） | **`edge`**（连线内嵌算子栈） | 折叠到对应数据边上，多步操作**竖直堆叠并以 `↓` 连接**，末尾标注最终输出 shape。点击任意一步仍可在检查器查看和编辑原节点参数，数据模型完全无损。 |

> **说明**：`ReduceSum` / `ReduceMean` 等带显式归约维度的轻量算子保持紧凑卡片显示（如 `sum()`、`mean(-1)`），确保规约语义一眼可见。

- 图像标准化用原生 `Normalize`。沿 `dim`（默认 `-3`）按给定统计量计算 `(x - mean) / std`，紧凑卡以圆点与线段表示均值偏移和标准差缩放。多组统计量显示 `Normalize · C=3` 等规格，单组显示 `Normalize · 广播`。
- 单进单出的 `TensorIndex` 与旧 `Slice` 可设为 `edge`。胶囊沿用源码索引写法，如 `[:, -1]`、`[:, 1:2]`、`[..., :2]`，并保留步长与参数表达式。分支、跨分区或控制边界，以及声明动态 `stop` 端口的切片均保留卡片。
- 真实 `Submodule` 使用带语义色条的紧凑顶栏，原型图标区分骨干、注意力、交叉注意力、前馈、投影、编码器、解码器、预测头与通用模块。标题最多两行，悬停可读全名，右上角 ↗ 可用键盘进入 forward()。
- 正文优先显示功能摘要，状态行标记本层真实步骤数及单一有效 Tensor 输出的 shape。契约占位使用琥珀色虚线徽标，真实展开使用青绿色徽标。原型、色标与摘要可用 `submoduleVisual` 配置。
- 端口标签置于独立网格带，左右两列各自逐行对齐外缘句柄，上下各占独立一行。同侧输入与输出连续排槽。插图、张量积木与模块共用外层句柄，范围框按卡片实测尺寸包围。

### 2.4 语义展开与 `SemanticOp` 使用红线

- **彻底展开**：模块内的关键变换（如参考点归一化、偏移量除以网格尺寸、权重 Softmax、特征重排为 2D 网格、双线性网格采样、逐点加权求和、多队列融合、输出投影与残差归一化）均须用真实算子与中间张量展开。
- **`SemanticOp` 的严格适用边界**：
  - **允许**：仅用于极简一元标量公式且 PyTorch 无独立具名层的小步变换（如 `[0, 1] → [-1, 1]` 的 `2x − 1`、按网格常数缩放的 `÷ [W=8, H=32]`），并以 `presentation: 'edge'` 折叠在连线上，同时写明 `label`、`formula` 与 `summary`。
  - **禁止**：不得用 `SemanticOp` 或贴图卡片（`visualMedia`）黑盒替代 PyTorch 原生算子（如 `F.grid_sample`、`torch.topk`、`nn.LayerNorm` 等）或掩盖多步张量变换。

### 2.5 布局泳道与亮/暗双主题实图验收

- 数据流严格**自左向右**按清晰水平泳道排布（如坐标支路、权重支路、特征值支路并行推进）。
- 汇合前上游节点尽量纵向对称对齐（如 `sampled_pts` 与 `attn_weights_5d` 上下对齐进入 `×`），连线上的竖直算子栈两侧保留充足留白，避免紧贴相邻卡片边缘或被跨线遮挡。
- 每次新增或重构重要子图后，必须运行：
  1. `agent.mjs validate <project> --draft`（确保 `ok: true`、`0` 异常节点）；
  2. 官方 Electron 渲染导出**亮色 + 暗色双主题 PNG 与局部特写**（`scripts/export-preview.cjs`），逐像素核查图标对比度、端口标签完整性、文字截断与连线遮挡。

## 三、Tensor Trail 程序设计与算子扩展规范

### 3.1 PyTorch 原生算子缺失必新建模块（7 项完成定义 DoD）

在阅读并绘制任何 PyTorch 模型时，只要遇到**PyTorch 自带算子或网络层**（`torch.*`、`torch.nn.*`、`torch.nn.functional.*`）在 Tensor Trail 注册表中尚未实现，**必须先在 Tensor Trail 中新建对应的原生模块**，再回到模型图中使用该原生模块绘图。

每个新增原生模块必须同时完成以下 **7 项闭环**，缺一不可：

| # | 闭环环节 | 具体工程要求与代码落点 |
| --- | --- | --- |
| 1 | **核心算子定义与注册** | 新建 `packages/model-core/src/modules/<op>.ts` 并在 `packages/model-core/src/modules/index.ts` 注册。端口遵循仓库惯例（主输入 `in` + 具名辅助端口如 `grid`，输出 `out` 或具名多输出）；参数沿用 PyTorch 名称与默认值；完整校验秩、dtype、已知数值边界（如正整数空间维、5D 限制）、符号维与同符号矛盾约束；输出为全新 Tensor，不泄漏输入的参数/缓冲区身份。 |
| 2 | **梯度上下文与信息源联动** | 接入 `packages/model-core/src/core/engine.ts` 与 `tensorAppearance.ts`：遵循「活动运行快照 `context.gradMode` 优先 → 项目超参数 `gradMode` → 默认 `grad`」规则；`no_grad` / `inference_mode` 强制关闭输出梯度（且阻断手工 `true` 覆盖）；`grad` 模式下按真实可微语义推导并允许手工标注覆盖。同步更新 `informationSources.ts`（如双输入数值算子加入 `mergedValues`）。 |
| 3 | **画布呈现分类注册** | 在 `packages/model-core/src/core/nodePresentation.ts` 按职责归类：纯形状整理入 `edgeOperatorTypes`；核心数学/网络层入 `compactLayerTypes`；二元汇合入 `compactJunctionTypes`。 |
| 4 | **专属图标与紧凑卡可读性** | 在 `packages/editor-ui/src/views/ModuleGlyph.tsx` 绘制语义清晰的专属 SVG 图标（标准卡与精简卡共用，兼顾亮/暗双主题对比度）。在 `ModuleNode.tsx` 与 `workbench.css` 配置 `compactLayerSpec()` 短规格；**多输入紧凑层卡必须常显全部端口标签**并按 `portSides` 动态留白（覆盖默认、反向、垂直及同侧布局）；缺线/报错时不伪装显示输入形状，存在 warning 时卡片与 tooltip 均可见警告。 |
| 5 | **检查器参数化帮助** | 在 `packages/editor-ui/src/editor/Inspector.tsx` 的 `operationHelp` 补充端口、坐标/维度约定与调用签名，使用参数变量形式（如 `F.grid_sample(in, grid, mode=..., padding_mode=..., align_corners=...)`），避免写死默认值导致用户切换参数后文案矛盾。 |
| 6 | **全量回归测试与门禁** | 新增核心单测（覆盖典型高维样例、符号维、矛盾约束、非法参数、全部 `gradMode` 与手工标注组合、双路信息源、Agent build/validate/序列化往返）、UI 紧凑卡测试（`compactFlow.test.ts`）与 CLI 烟测（`packages/cli/scripts/test-cli.mjs`）。必须全部通过：`npm run build:agent`、`npm run typecheck`、`npm test`、`npm run test:cli`、`npm run build:desktop`。 |
| 7 | **规范与操作文档同步** | 同步更新 [AI 操作指南](AI操作指南.md) 与 [模型绘图规范与验收清单](模型绘图规范与验收清单.md) 中的算子规格、配方示例与验收要点。 |

### 3.2 参数化可视化与交互工具设计准则

- **所有张量视觉属性 API 化与面板化**：任何经常需要调整的张量展示参数（`mode`、`tone`、`color`、`depthStyle`、`width`、`boxWidth`、`boxHeight`、`boxDepth`、`axisLabels`、`caption`）都必须同时通过 `set_node_tensor_visual` API 与检查器实时面板（`TensorVisualPanel.tsx`）开放，支持撤销/重做与 JSON 持久化。
- **数据模型无损投影**：画布精简展示（连线竖直算子栈 `presentation: 'edge'`、紧凑图标卡 `presentation: 'compact'`）必须在只读投影层（`packages/model-core/src/core/canvasProjection.ts`）完成，**严禁改写底层 DAG 节点、端口或形状推导结果**；展开、点击单步编辑参数、CLI 校验与保存往返均保持 100% 无损。
- **高频构图动作提供一键交互**：如输入 1 对 1 拆分（`splitInputFanout`）、标准卡与精简图标卡切换，既支持 UI 一键操作，也支持 AI 通过标准 Patch API 批量构造。

### 3.3 增量编辑安全与研发协作门禁

- **改图必须走官方 API**：始终使用 `agent.mjs patch --draft --layout preserve` 与 `agent.mjs validate --draft`，禁止手改持久化 `.tensor-trail.json`，禁止修改被绘模型的源代码来迎合架构图，改动前先核对现有节点坐标以保留用户手动拖拽成果。
- **软件升级走独立审查闭环**：涉及新增算子、核心引擎或画布渲染升级时，严格执行「基线快照 → 只读调研定方案 → 授权范围实施与自测 → 独立只读代码审查与缺陷闭环 → Electron 亮/暗双主题实图验收」。
